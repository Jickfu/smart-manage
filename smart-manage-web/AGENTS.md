# 前端开发规则

本文件适用于 `smart-manage-web`。同时继承根目录 `AGENTS.md`。

## 技术与目录

- 使用 pnpm、React、TypeScript 和 Ant Design，不引入其他 UI 组件库。
- 使用 `@/` 别名引用 `src`。
- 业务页面按 `src/domain/{领域}/{应用}/{单据}` 组织。
- 页面组件目录使用 PascalCase，工具和 Hook 文件使用 camelCase。
- 前端 ID 必须使用 `string`，避免雪花 ID 精度丢失。

## 页面与状态边界

- 页面壳层只负责布局、加载、错误、权限和按钮区。
- 表单或列表基础组件负责字段渲染、过滤器、表格和引用选择器。
- 领域页面负责状态流转、Mutation、明细聚合和业务命令。
- TanStack Query 管理服务端状态，Zustand 管理跨页面客户端状态，Ant Design Form 管理编辑状态。
- 服务端查询使用 `useQuery`；保存、提交、删除和高风险命令使用 `useMutation` 或项目领域命令封装。
- 每个业务单据维护 Query Key Factory，至少包含 `all`、`lists`、`list(params)`、`details` 和 `detail(id)`。
- 禁止在页面中重复维护通用提交 loading 和通用错误提示。

## 页面注册与单据生命周期

- 页面只能通过 `pageRegistration.ts(x)` 白名单注册，禁止根据后端字符串、文件名或目录任意动态加载。
- 页面键重复、空注册清单或生成结果不一致必须直接失败，不保留兼容逻辑。
- 列表页单实例；编辑页按真实 ID 多实例；新增页每次使用新的临时 UUID。
- 编辑和查看同一单据共用同一个 tab key。
- 新增保存成功后重新查询详情，并将临时 tab key 替换为真实单据 tab key。
- 保存成功后不关闭编辑页，继续留在当前单据页面。
- 保存和提交必须区分；已提交等只读状态进入 `VIEW`，禁止普通保存。
- 新增和编辑页都必须注册脏数据关闭保护。
- 即使没有明细，主从单据也必须使用 `entrys: []`。
- 业务详情、记录详情和只读查看必须使用工作台通用编辑/查看页签，禁止使用 `Drawer` 抽屉承载；抽屉只允许用于不形成独立页面的临时辅助操作。

## 样式与校验

- 自定义页面应优先复用通用页面壳层，并以通用编辑页作为默认视觉基准：主要操作按钮统一置于页面顶部操作区，内容区使用白色背景的折叠面板组织信息，控件尺寸、间距、标签布局和只读表现与同类通用页面保持一致。只有控制台、大屏等交互形态确实不同的页面可以偏离；偏离时必须由业务交互需要驱动，禁止为单个页面另造一套视觉风格。
- 业务弹框中的表单同样以通用 `EditPage` 为视觉基准：文本、密码、日期、选择等字段默认使用下边框（`underlined`）控件，字段宽度和跨列宽度复用通用编辑页的 `230px`、`524px` 规格；仅在搜索框、紧凑工具栏或业务内容确需自适应宽度时偏离。
- 业务弹框默认复用 `src/domain/common/component/AppModal.tsx`；只有简单提示、确认和结果反馈弹框可以直接使用 Ant Design Modal。标题位于左侧，搜索或筛选等扩展操作通过 `headerExtra` 提供，关闭使用壳层统一的 Ant Design 原生关闭按钮，内容滚动通过 `bodyMode` 控制，底部操作通过 `footer` 提供。业务组件不得重复实现 Modal 容器、标题栏、关闭按钮和底部操作区；固定高度或左栏右内容等特殊布局只能在 `AppModal` 内容区内部实现。
- 通用列表、引用选择器及其他包含横向滚动表格的固定高度界面，必须建立从页面或弹框内容区到 `.ant-table-body` 的完整 flex 高度链，并让横向滚动条固定在表格所属内容区最下方；禁止使用固定 `scroll.y` 或内容高度撑开表格，导致横向滚动条紧贴最后一条数据行。优先复用 `ListTableShell`、`ListPage` 或 `RefSelector` 已有布局。
- 除应用入口列表 `src/pages/app/AppsView.tsx` 及其配套样式外，页面内容区与工作台边界、同级卡片或块状内容容器之间统一保留 `10px` 间隔；使用通用页面壳层的 CUSTOM 页面不得重复叠加页面级 padding，独立 CUSTOM 页面自行提供 `10px` 内容区边距。该规则不约束卡片内部排版、表单字段、按钮组、工具栏、图表元素等组件内部间距。
- 页面头部必须承载实际操作、筛选或状态内容；没有头部内容时不得渲染空白占位。CUSTOM 页面中的数据表默认关闭表格内置底部分页，并将分页置于表格所属卡片或区块的右上角元信息区，与通用列表页保持一致。
- 禁止在 TSX 中编写 CSS 或内联 `style`。
- 自定义 CSS 类名以 `sm-` 开头，优先使用 flex 布局。
- 公共 `ListPage` 的列定义必须至少保留一个未设置 `width` 的业务列，用于吸收表格剩余空间，避免选择列和序号列被同比放大。
- 通用列表界面的左侧树在没有明确特殊要求时必须提供语义清晰的根节点，并默认展开根节点；不得直接以多个业务节点作为顶层入口。
- 未有明确需求时，列表页和表单内表格均禁止新增“操作”列；需要对记录执行操作时，使用多选列选择记录，并将操作按钮集中放置在表格上方的合适位置。查看或编辑等常规入口优先复用可点击的业务标识列和页面统一操作区。
- 未有明确需求时，按钮只显示文字，不添加图标。
- 表单字段校验由 Ant Design Form 负责；没有明确的外部不可信数据校验需求时不引入重复校验模型。
- ESLint 报错时，未经用户允许不得用注释跳过，也不得修改 `eslint.config.js` 降低规则。
- 只有需要自动修复格式或用户明确要求时才执行 `pnpm lint:fix` 或 `pnpm format`。

## 验证

修改前端代码至少执行：

```bash
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

涉及页面注册时还必须执行 `pnpm gen:registry`，并确认生成结果已提交且再次生成无差异。
