# 工作流领域

本领域是可选的审批能力，使用 Warm-Flow 1.8.9。定义、版本、活动任务、候选人和审批历史由引擎管理；Smart Manage 负责业务绑定、入口权限、实例参与资格、事务、快照和通知。不得平行维护第二套引擎状态或流程 DSL。

## 交付与依赖

一个 Maven artifact `smart-manage-domain-workflow`，依赖 platform；按 definition、instance、runtime、task、assignment、engine、notification 划分职责。Warm-Flow Java 类型只能存在于 engine/warmflow。接入方只依赖 runtime/contract 和 instance/contract。

`demo` 的请假样板依赖 workflow。移除 workflow 时须同时移除或改造其接入业务；platform 不依赖这两个领域。前端通过领域 extensions 注册懒加载视图，平台消息中心只认识视图扩展契约。

## 定义与设计器

每个业务类型绑定一个流程编码，创建时选择已装配业务，复制版本继承绑定。定义使用引擎原生保存、复制和发布；已发布或使用的版本禁止改写。发布新版本时，旧发布版本统一保留为引擎过期状态，不能因尚未运行实例而退回草稿；旧版本可复制生成新草稿。停用只阻止新发起，现有任务仍可处理。保存和发布校验当前设计摘要，绑定行锁与流程编码锁协调并发。

官方 Vue 设计器仅在 iframe 中加载，原生 React 提供定义管理、任务和业务审批。UI 源码固定为官方 v1.8.9 提交 `37b17a8939f0931ab8c19d66b768050325da3bcf`；构建使用其公开组件和 DataProvider，不修改上游画布。后端 package 阶段生成并嵌入静态资源，源码和依赖通过 SHA 与锁文件固定。

经典画布的节点与文字坐标分别保存。DataProvider 在展示副本中补齐缺失或无效的文字坐标，保留已有有效位置；定义设计和历史流程图使用相同适配。读取不修改已发布定义、历史快照或服务端并发摘要，草稿保存时再写入完整坐标。仿钉钉模式沿用官方布局。

设计器与平台同源，使用 HttpOnly 会话 Cookie；CSRF Token 只存内存，不进入 URL 或 localStorage。所有数据请求经过 Smart Manage Controller，禁止直接开放上游通用管理 API。跨窗口消息须同时检查 origin、source、channel、定义 ID 与载荷类型。保存失败保留编辑内容，关闭前确认脏数据。

设计器采用工作台独立内容页签，以定义版本 ID 唯一定位；重复打开激活已有页签，切换页签保留画布，关闭释放 iframe。已发布版本只读，历史流程图仍使用审批页内的临时查看弹框。定义列表使用“全部流程 → 领域 → 应用”的左树和右侧分页表格，树范围与流程编码/名称关键词共同作为服务端查询条件；切换范围、搜索或翻页清除行选择。列表使用复选框，单记录命令仅在选中一条时启用；只显示最新版本与版本总数，流程编码链接打开最新设计。顶部“版本管理”按流程绑定 ID 复用独立内容页签，版本倒序分页并支持版本号搜索；设计、复制、发布集中在版本列表顶部，翻页和搜索清除选择，版本号链接打开指定版本设计。表格均不设操作列。新增流程定义复用 `ModalEditPage`，业务类型通过 `RefSelector` 选择已装配的业务，展示编码和名称、提交稳定业务 key；字段校验、布局和页脚由公共模板提供，业务保留未保存关闭保护。发布只针对已保存版本。

业务参照采用左树右表：左侧“全部审批业务 → 领域 → 应用”，右侧展示已装配审批业务的编码、名称及所属应用，支持范围与关键词组合筛选。接入资格来自 `WorkflowBusiness` 注册，不能从功能目录或菜单自动推定。接入方显式声明 `featureKey`，由平台 `FeatureDirectoryReader` 按真实关联查询目录身份及当前名称；不得拆分业务 key 猜测归属，同名应用按 ID 区分。缺失有效目录关联时明确拒绝查询，不静默归入“其他”。

树当前止于应用，右表承担具体审批业务或流程定义的展示与选择，避免再加一层功能后重复展示同一对象；只有出现同一功能下多个独立审批业务的实际需求时才重新评估功能层。菜单属于导航配置，可缺失、重复或因用户权限不同而变化，不作为审批业务分类依据。目录可见性不是审批授权；业务目录查询使用定义列表权限，创建、设计和发布仍分别执行自身权限。

静态入口使用 `Cache-Control: no-cache`，升级后重新校验 HTML 与资源，避免沿用旧入口引用。适配层负责官方人员回显数组与项目查询协议转换，不修改上游画布。

一期允许开始、结束、审批和条件网关，审批仅支持或签。发布要求无环、全部节点可达、人工节点配置审批人、网关有且仅有一条默认分支。条件仅允许业务开放字段上的原生比较表达式 `eq/ne/gt/ge/lt/le@@字段|常量`；数值字段使用数值常量，文本字段仅允许等于/不等于非数字文本。非默认分支必须互斥，包含边界重叠或不能证明互斥的不同字段条件时拒绝发布，不能依赖保存顺序。监听器、脚本、自定义表单、任意节点跳转、循环、并行、会签和退回连线均由服务端拒绝。

## 运行与业务事务

业务先持有主单锁，再取得绑定或引擎实例锁。保存/提交、引擎推进、业务结果更新、快照附件引用、幂等回执和通知 Outbox 必须在同一数据库事务中提交。业务失败、无有效候选或后续节点失败会回滚本次推进。

申请人、单据组织和条件变量由业务服务端提供，不能采用浏览器上传的审批事实。审批人支持指定用户、单据组织的角色成员和负责人，在节点激活时解析并冻结；角色后续修改不会偷偷改变当前任务。本人在候选集合时允许手动审批，不自动跳过。

拒绝表示终止本轮。申请人可修改单据后重新提交，生成新实例；每轮快照及历史不被新内容覆盖。撤回只能由申请人执行，且本轮尚无实际审批完成；提交和任务创建不算审批，候选人维护也不算。撤回结束本轮，绝不映射为会重新生成任务的引擎 revoke。首审批与撤回在同一主单/实例锁下竞争。

提交和审批/撤回使用 UUID 请求标识和内容摘要。成功后相同主体、相同请求内容重放原结果；同一标识携带不同内容被拒绝。失败回滚不保留成功回执。

## 授权与维护

管理功能权限不授予业务数据读取权。申请人、当前候选人及该轮实际历史处理人可读取该轮快照、审批记录和所引用附件。业务普通列表和编辑仍执行业务功能权限与 DataScope，审批读取不扩大这些权限。

当前任务候选人维护使用独立权限 `workflow:process:task:maintain`，管理员通过实例 ID 定位当前任务，选择有效用户并填写原因。记录操作人、任务、时间及变更前后候选人；不代审批、不推进节点、不插入伪审批记录。维护入口只返回定位所需信息，不返回单据快照或附件。角色解析后的候选集合不以回显请求的 100 条上限截断，前端分批回显，全部成功后再允许维护。

## 通知与裁剪

业务事务仅写 Outbox，Quartz 的 `DispatchWorkflowNotificationJob` 在提交后调用平台 Inbox Contract。固定事件键去重，短事务领取带租约的批次，失败保留并延迟重试；消息故障不得回滚已提交审批。通知文本不携带业务敏感详情，打开业务时重新验证实例权限。

平台调度器识别来自未装配领域的历史任务定义：保留数据库定义、移除实际调度并记录不可用原因。已装配领域中的错误类名仍报错，不能用这一规则掩盖配置问题。

## 接入与验证

新业务实现 `WorkflowBusiness`，声明业务身份、显式关联的 `featureKey` 和条件字段，提供主单锁及完成回调；通过 `WorkflowSubmission` 发起，通过 `WorkflowHistoryReader` 核验历史实例参与资格。业务拥有自己的审批快照和附件保留规则，不能从当前主单拼出旧轮次详情。

验证遵守[质量验证](../../../../../docs/development/verification.md)。真实 PostgreSQL 测试必须覆盖或签唯一处理、首审批与撤回竞争、拒绝/重提、业务回滚、候选变更、条件边界和历史轨迹；Mock 不能替代事务验收。当前实施证据和未完成项见[实施进度](../../../../../docs/proposals/workflow-implementation-progress.md)。
