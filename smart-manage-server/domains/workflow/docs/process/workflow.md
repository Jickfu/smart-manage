# 工作流领域

本领域是可选的审批能力，使用 Warm-Flow 1.8.9。定义、版本、活动任务、候选人和审批历史由引擎管理；Smart Manage 负责业务绑定、入口权限、实例参与资格、事务、快照和通知。不得平行维护第二套引擎状态或流程 DSL。

## 交付与依赖

一个 Maven artifact `smart-manage-domain-workflow`，依赖 platform；按 definition、instance、runtime、task、assignment、engine、notification 划分职责。Warm-Flow Java 类型只能存在于 engine/warmflow。接入方只依赖 runtime/contract 和 instance/contract。

`demo` 的请假样板依赖 workflow。移除 workflow 时须同时移除或改造其接入业务；platform 不依赖这两个领域。前端通过领域 extensions 注册懒加载视图，平台消息中心只认识视图扩展契约。

## 定义与设计器

每个业务类型绑定一个流程编码，创建时选择已装配业务，复制版本继承绑定。定义使用引擎原生保存、复制和发布；已发布或使用的版本禁止改写。发布新版本时，旧发布版本统一保留为引擎过期状态，不能因尚未运行实例而退回草稿；旧版本可复制生成新草稿。停用只阻止新发起，现有任务仍可处理。保存和发布校验当前设计摘要，绑定行锁与流程编码锁协调并发。

官方 Vue 设计器仅在 iframe 中加载，原生 React 提供定义管理、任务和业务审批。UI 源码固定为官方 v1.8.9 提交 `37b17a8939f0931ab8c19d66b768050325da3bcf`；构建使用其公开组件和 DataProvider，不修改上游画布。后端 package 阶段生成并嵌入静态资源，源码和依赖通过 SHA 与锁文件固定。

经典画布的节点与文字坐标分别保存。DataProvider 在展示副本中补齐缺失或无效的文字坐标，保留已有有效位置；定义设计和历史流程图使用相同适配。读取不修改已发布定义、历史快照或服务端并发摘要，草稿保存时再写入完整坐标。仿钉钉模式沿用官方布局。

设计器与平台同源，使用 HttpOnly 会话 Cookie；CSRF Token 只存内存，不进入 URL 或 localStorage。所有数据请求经过 Smart Manage Controller，禁止直接开放上游通用管理 API。跨窗口消息须同时检查 origin、source、channel、定义 ID 与载荷类型。保存失败保留编辑内容，关闭前确认脏数据。

设计器采用工作台独立内容页签，以定义版本 ID 唯一定位；重复打开激活已有页签，切换页签保留画布，关闭释放 iframe。已发布版本只读，历史流程图仍使用审批页内的临时查看弹框。定义列表使用“全部流程 → 领域 → 应用”的左树和右侧分页表格，树范围与流程编码/名称关键词共同作为服务端查询条件；切换范围、搜索或翻页清除行选择。列表使用复选框，单记录命令仅在选中一条时启用；只显示最新版本与版本总数，流程编码链接打开最新设计。顶部“版本管理”按流程绑定 ID 复用独立内容页签，版本倒序分页并支持版本号搜索；设计、复制、发布集中在版本列表顶部，翻页和搜索清除选择，版本号链接打开指定版本设计。表格均不设操作列。新增流程定义复用 `ModalEditPage`，业务类型通过 `RefSelector` 选择已装配的业务，展示编码和名称、提交稳定业务 key；字段校验、布局和页脚由公共模板提供，业务保留未保存关闭保护。发布只针对已保存版本。

业务参照采用左树右表：左侧“全部审批业务 → 领域 → 应用”，右侧展示已装配审批业务的编码、名称及所属应用，支持范围与关键词组合筛选。接入资格来自 `WorkflowBusiness` 注册，不能从功能目录或菜单自动推定。接入方显式声明 `featureKey`，由平台 `FeatureDirectoryReader` 按真实关联查询目录身份及当前名称；不得拆分业务 key 猜测归属，同名应用按 ID 区分。缺失有效目录关联时明确拒绝查询，不静默归入“其他”。

树当前止于应用，右表承担具体审批业务或流程定义的展示与选择，避免再加一层功能后重复展示同一对象；只有出现同一功能下多个独立审批业务的实际需求时才重新评估功能层。菜单属于导航配置，可缺失、重复或因用户权限不同而变化，不作为审批业务分类依据。目录可见性不是审批授权；业务目录查询使用定义列表权限，创建、设计和发布仍分别执行自身权限。

静态入口使用 `Cache-Control: no-cache`，升级后重新校验 HTML 与资源，避免沿用旧入口引用。适配层负责官方人员回显数组与项目查询协议转换，不修改上游画布。

当前定义允许开始、结束、人工审批、脚本和条件网关，人工审批仅支持或签。脚本在 Warm-Flow 中保存为带 `smNodeType=SCRIPT` 扩展标记的中间节点，不 fork 引擎节点类型。发布要求无环、全部节点可达、人工节点配置审批人、脚本节点无人工审批人且只有一条出线、网关有且仅有一条默认分支。条件仅允许业务开放字段上的原生比较表达式 `eq/ne/gt/ge/lt/le@@字段|常量`；数值字段使用数值常量，文本字段仅允许等于/不等于非数字文本。非默认分支必须互斥，包含边界重叠或不能证明互斥的不同字段条件时拒绝发布，不能依赖保存顺序。任意监听器、自定义表单、循环、并行、会签和退回连线仍由服务端拒绝。

## 运行与业务事务

业务先持有主单锁，再取得绑定或引擎实例锁。保存/提交、引擎推进、业务结果更新、快照附件引用、幂等回执和通知 Outbox 必须在同一数据库事务中提交。业务失败、无有效候选或后续节点失败会回滚本次推进。

工作流领域只维护流程运行事实，并通过 `WorkflowBusiness.completed` 返回 `APPROVED`、`REJECTED`、`WITHDRAWN`、`TERMINATED` 结果；它不拥有、不读取、也不直接修改业务单据状态。接入业务按[单据状态架构](../../../../../docs/architecture/bill-status.md)在自己的完成回调中映射结果。请假样板将通过映射为 C（已审核），将其他结束结果映射回 A（暂存），但该映射不是工作流平台的全局假设。

申请人、单据组织和条件变量由业务服务端提供，不能采用浏览器上传的审批事实。审批人支持指定用户、单据组织的角色成员和负责人，在节点激活时解析并冻结；角色后续修改不会偷偷改变当前任务。本人在候选集合时允许手动审批，不自动跳过。

拒绝表示终止本轮。申请人可修改单据后重新提交，生成新实例；每轮快照及历史不被新内容覆盖。撤回只能由申请人执行，且本轮尚无实际审批完成；提交和任务创建不算审批，候选人维护也不算。撤回结束本轮，绝不映射为会重新生成任务的引擎 revoke。首审批与撤回在同一主单/实例锁下竞争。

提交和审批/撤回使用 UUID 请求标识和内容摘要。成功后相同主体、相同请求内容重放原结果；同一标识携带不同内容被拒绝。失败回滚不保留成功回执。

## 授权与维护

管理功能权限不授予业务数据读取权。申请人、当前候选人及该轮实际审批或任务协作处理人可读取该轮快照、审批记录和所引用附件；终止、节点调整、脚本重试等管理操作人以及脚本系统身份不能据此取得参与人资格。业务普通列表和编辑仍执行业务功能权限与 DataScope，审批读取不扩大这些权限。

当前任务候选人维护使用独立权限 `workflow:process:task-monitor:maintain`，入口位于流程实例的当前任务上下文中，自动带入实例和任务，选择有效用户并填写原因。记录操作人、任务、时间及变更前后候选人；不代审批、不推进节点、不插入伪审批记录。维护入口只返回定位所需信息，不返回单据快照或附件。角色解析后的候选集合不以回显请求的 100 条上限截断，前端分批回显，全部成功后再允许维护。

## 管理后台与运行控制

工作流应用只提供流程定义、流程实例、任务监控和流转日志四个管理入口；普通参与人的待办、已办和我发起从全局消息中心进入，不提供工作流“任务中心”菜单。管理菜单和命令分别使用稳定 Feature 与权限码，拥有入口权限不自动获得其他命令权限或业务正文读取权。

流程实例详情组合实例状态、当前任务、候选人、脱敏运行变量、审批历史和管理操作记录。敏感名称的变量值在服务端递归清除后才返回管理页面。支持挂起、恢复、终止、管理员退回或向后跳转、挂起状态下修改普通变量，以及脚本失败后的重试。存在多个活动任务时，节点调整必须显式选择任务，不能按列表顺序隐式取第一项。目标节点由服务端从发起时定义计算；不能选择当前节点，退回只能选择已经流转的节点，向后跳转只能选择尚未流转的节点。实例禁止删除，结束后仍保留任务历史、脚本记录和管理审计。

引擎历史在适配层分类为审批、任务协作、管理操作和脚本执行。普通参与人的“审批记录”只返回审批类历史；管理端分别展示完整流转轨迹、候选人维护和管理记录。全局流转日志可展示动作、处理人和时间，但不返回审批意见正文；审批意见只能通过业务单据或参与人详情读取。

每个管理命令先锁业务主单，再锁引擎实例，使用 UUID 请求标识及内容摘要实现幂等。命令必须填写原因，并写入 `t_workflow_operation` 的操作人、任务、动作及前后投影。挂起不改变业务状态；终止产生独立 `TERMINATED` 结果并由业务回调自行解释。流程变量修改要求实例先挂起，禁止修改业务、申请人、组织、实例、定义及 `sm.`、`warm.` 命名空间，单次最多 100 项且修改载荷不超过 100KB。

当前处理人可转办、委派、加签、减签和拿回。转办与委派产生的 Warm-Flow 人员类型必须纳入待办、详情和任务监控的真实办理资格。减签只接受当前引擎能够移除的人员；无效操作由引擎拒绝并整体回滚。拿回依据该处理人的最近已办记录退回，并将返回任务明确交还该实际处理人，避免仅按定义重新解析后本人无法继续办理。

## 脚本节点

脚本节点读取只含实例、定义、节点和当前流程变量的 JSON `workflow` 上下文，返回 `{ variables, participants }`。`variables` 是最多 100 项、总计不超过 100KB 的普通变量增量；`participants` 是最多 100 名启用用户，只覆盖紧随脚本节点创建的人工任务候选人。脚本不能访问 Spring Service、Java 类、数据库、网络、文件、消息、进程、线程或原生能力。

平台提供与 workflow 无关的 `RestrictedScriptExecutor`：每次执行创建独立 GraalJS Context，HostAccess 为 NONE，限制源码长度、并发数、执行时间，以及返回值的层级、节点数、集合规模和字符串字节数；循环引用或超过 100KB 的结构化结果在转换过程中直接失败。workflow 负责解释结构化结果、写入 `t_workflow_script_execution`、合并变量和推进任务。脚本失败或超时不越过节点，保留脚本任务并挂起实例；管理员可先维护允许的变量，再执行受审计重试或选择跳转、终止。运行实例始终使用发起时固化的已发布定义脚本。

## 业务单据历史轮次

`WorkflowHistoryReader` 提供两类读取：消息中心和参与人页面使用当前登录人的申请人、候选人或历史处理人资格；业务单据页面先由业务领域执行自己的详情权限与 DataScope，再通过受信任契约读取该 `businessType + businessId` 的全部轮次和不可变快照。业务页面不得直接把后者暴露为无权限工作流 API。

请假样板在单据顶部提供“查看工作流”和“审批意见”，支持按轮次切换流程图、提交时单据快照、附件和审批记录。重提生成新实例，不覆盖旧轮次；管理操作在流程管理投影中单独显示，不冒充审批意见。

## 通知与裁剪

业务事务仅写 Outbox，Quartz 的 `DispatchWorkflowNotificationJob` 在提交后调用平台 Inbox Contract。固定事件键去重，短事务领取带租约的批次，失败保留并延迟重试；消息故障不得回滚已提交审批。通知文本不携带业务敏感详情，提示参与人从消息中心打开，打开业务时重新验证实例权限。

平台调度器识别来自未装配领域的历史任务定义：保留数据库定义、移除实际调度并记录不可用原因。已装配领域中的错误类名仍报错，不能用这一规则掩盖配置问题。

## 接入与验证

新业务实现 `WorkflowBusiness`，声明业务身份、显式关联的 `featureKey` 和条件字段，提供主单锁及完成回调；通过 `WorkflowSubmission` 发起，通过 `WorkflowHistoryReader` 核验历史实例参与资格。业务拥有自己的审批快照和附件保留规则，不能从当前主单拼出旧轮次详情。

验证遵守[质量验证](../../../../../docs/development/verification.md)。真实 PostgreSQL 测试必须覆盖或签唯一处理、首审批与撤回竞争、拒绝/重提、业务回滚、候选变更、条件边界、历史轨迹、挂起/恢复、变量修改、终止、跳转、转办/委派/加减签、拿回以及脚本成功与失败挂起；Mock 不能替代事务验收。当前实施证据和未完成项见[实施进度](../../../../../docs/proposals/workflow-implementation-progress.md)。
