# 请假申请样板

独立请假聚合位于 `sm.domain.demo.office.leave`，前端位于 `src/domain/demo/office/leave`。它展示业务单据接入[工作流领域](../../../workflow/docs/process/workflow.md)的完整边界，现有采购申请不接入此审批流程。

## 业务规则

编号首次保存或直接提交时，在业务事务内调用平台编号生成器；默认 `LV-{bill.bizDate:yyyyMMdd}-{seq:5}`，按组织和业务日期分别计数，数据库按组织与编号唯一。申请人及组织取当前会话，不接受客户端替换。

请假类型、起止时间、人工填写的天数和原因属于主单。结束必须晚于开始，天数为正且最多两位小数；不计算假期余额、工作日或考勤。审批条件开放 `days` 数值字段和 `leaveType` 文本字段。

状态 A 可编辑、B 审批中、C 通过。拒绝或撤回结束本轮并回到 A，最近结果保存在 lastOutcome，最近实例引用保留。重新提交使用新实例并清空最近结果。已打开的查看页签在撤回或拒绝回到 A 后恢复编辑；同一提交命令失败重试复用 requestId，新轮次使用新 requestId。只允许申请人修改草稿；删除仅允许从未提交过的草稿。普通列表/详情/保存/提交/删除分别执行功能权限和 DataScope，SELF 对应申请人。

## 快照与附件

提交时保存服务端生成的单据快照，并为所选附件保存该轮不可变引用。审批详情只读取指定实例的快照，并核对实例与业务 ID 的绑定；不把后来修改的单据显示成历史内容。

已被历史引用的附件不能物理删除或修改备注，但新草稿可取消选择，历史引用仍保留。普通附件读取要求业务详情范围且属于当前选择；历史附件读取要求有权参与引用它的那一轮。附件修改在平台实际写事务中锁定主单并复查冻结状态，防止审批提交与附件删除并发。附件提升、删除和备注修改遵循业务主单→附件→业务映射的锁序；临时附件在等待锁期间已被提升时，原删除或备注请求必须失败并要求刷新，不能沿用空业务归属。

## 页面与接入

编辑页复用 EditPage；审批页顶部为返回、流程图和有资格时的撤回按钮，左侧为只读快照，右侧为独立的任务表单和审批记录页签。侧栏不继承主单 Form 的禁用上下文，意见区可滚动、提交按钮固定。未提交意见在返回、页签关闭和容器替换时必须受到保护。

demo 在 Maven 和前端 `dependencies.json` 明确依赖 workflow；排除 workflow 时同时排除 demo，或由二开项目先移除该接入样板。platform-only 发行仍可独立使用。
