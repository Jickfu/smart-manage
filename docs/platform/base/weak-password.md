# 弱口令管理与固定密码策略

## 模块边界

弱口令管理属于 `sys/base/weak-password`，维护全系统共用的本地拒绝词库。页面采用列表与 `ModalEditPage` 通用弹窗编辑，菜单位于系统管理的“系统配置”分组；公开维护 Service 的 `@AdministratorOnly` 复核真实管理员身份。

管理员可以查询、新增、编辑和删除词条。词条本身是匹配身份，不额外引入业务编码、组织范围、启停状态或策略参数配置页。保存和删除有版本检查，数据库唯一约束保护并发重复写入。保存操作只记录动作，不记录词条请求和响应正文。

词库只保存公共拒绝词条，不保存或关联实际用户密码。不要将正在使用的真实密码录入词库。

## 匹配和初始化

- `t_sys_weak_password.word` 保存完整词条，长度为 1～64 个 Unicode 码点，不能全为空白或包含控制字符、无效代理字符；不去除首尾空格。
- 匹配时先做 NFC 规范化，再使用 `Locale.ROOT` 转为小写，按完整词条匹配，不做包含关系匹配。用户真实密码不因此转小写或改变字符序列。
- `match_digest` 保存规范化词条的 SHA-256 摘要并建立唯一索引。校验查询只传摘要，避免候选密码明文进入 SQL 参数诊断；此摘要只用于词库匹配，不替代用户密码的 Argon2 存储。
- 密码策略直接读取 PostgreSQL，不缓存词库；数据库异常时拒绝设置密码，不降级跳过检查。维护事务提交后开始的后续策略查询读取新结果，已完成检查的在途改密不追溯取消。
- 安装时初始化本地拒绝词库，保留短于密码最小长度的词条。词库不是全面泄露密码库，不依赖外部查询服务；后续启动不覆盖管理员维护的数据。新增词条不预填描述。

## 固定密码策略

新密码必须为 15～64 个 Unicode 码点，允许空格和长口令，不要求混合大小写、数字或符号。拒绝全空白、控制字符、无效代理字符以及本地词库命中项；同时拒绝去除数字、符号和空格后仅剩账号名或 Smart Manage 名称的简单变体，不按子串拒绝正常长口令。

`PasswordPolicyService` 是新密码策略的统一入口。创建用户、首次强制改密、个人中心原密码改密、邮箱改密和找回、管理员重置、导入用户及管理员首次安装初始化均在凭据写入前校验。用户列表重置和导入生成 20 位安全随机密码，并复用策略校验。

前端字段通过标题右侧问号悬浮提示展示规则（通用字段传入 `tooltip`，手写表单使用 `Form.Item.tooltip`）；独立登录页使用新密码输入框右侧问号提示，不额外占用纵向空间。前端使用 Unicode 码点计数做即时格式提示，完整弱口令判断由后端执行；不提供匿名密码探测接口。密码不截断、不去空格，允许密码管理器填充和粘贴；不引入定期改密。

## 初始管理员与升级

初始化数据以空密码作为不可登录的标记。所有环境首次启动自动生成 20 位安全随机临时密码，通过统一策略后写入数据库，并将明文仅保存到运行位置的 `administrator-initial-password.txt`；IDEA 使用运行配置工作目录，打包 JAR 使用 JAR 所在目录。文件只允许当前运行用户读写，日志不得输出密码；运维人员获取后必须删除。数据库条件更新保证多实例仅初始化一次，初始化后首次登录强制改密；再次启动不生成或覆盖既有密码。

部署与后续升级遵守[数据库升级规则](../../development/database.md#正式发布与升级规则)。

验证遵守[质量验证](../../development/verification.md)，覆盖策略拒绝路径、真实管理员边界、词条唯一性和乐观锁、跨会话生效、事务回滚及基线初始化和再次启动数据保留。
