# 角色管理

角色编码是普通业务标识，不承担系统管理员身份。管理员账号保护与数据范围绕过遵守[安全架构](../../architecture/security.md)和[数据权限设计](../../architecture/data-permission.md)。

## 功能权限分配

左侧范围树按“全部权限 → 领域 → 应用 → 功能／应用级权限”组织，初始展开领域以直接显示应用。领域归属由权限所属应用的真实 `domain_id` 提供，不从权限编码或功能键推断；各层显示已选数与总数，点击节点只筛选右侧权限。

领域范围汇总其下全部应用的权限，右侧保留所属应用和所属功能列；关键字支持权限编码、名称、领域、应用及功能。全选与清空仅作用于当前筛选结果，切换范围保留其他范围的选择，保存仍只提交具体权限 ID。

## 数据范围分配

页面保持独立的分配命令：请求由 `roleId`、`version`、`defaultDataScope`、`rules` 组成，保存沿用版本检查和事务整体替换。普通角色资料保存不修改数据范围。所有新角色默认 `SELF`；已有 `ALL` 仅通过显式分配命令改变。

基本信息和资源例外使用公共编辑分区。基本字段复用 `FormFieldGrid/Cell`，规则复用 `EditableDetailTable`，新增和批量删除集中于规则分区标题栏。删除只修改本地草稿，保存时统一提交。顶部按钮区不展示右侧摘要，但仍保留未保存修改的关闭保护；其他分配页沿用 `AssignmentPage` 默认摘要行为。

每条草稿规则具有稳定的本地行标识，编辑业务字段不改变标识，重复规则也可分别选择、删除。行标识必须显式排除在业务比较、校验和请求之外。规则顺序及组织顺序不产生脏状态；改回原业务值重新变为干净状态。

切换资源只清除原操作，不清除数据范围与组织 ID；操作候选由服务端注册表提供，不额外维护业务键映射。临时切换出自定义组织范围时保留组织 ID，切回后恢复。保存前拒绝重复的资源/操作规则和空自定义组织范围；后端仍执行最终校验。

## 组织选择边界

自定义组织使用公共 `RefSelector` 多选。当前阶段仅消费既有 `orgApi.options()`，由角色模块适配本地关键字搜索和分页，作为现有全量候选接口的明确例外。不得直接套用具有“选择上级组织”语义的 `useOrgRefSelector`，也不增加组织树、上级组织分页接口或其 LIST/DETAIL 权限依赖。

已配置但候选列表暂未返回的组织 ID 以“未解析组织（ID）”记录保留在已选项中，不臆造名称、不加入候选列表。候选更新后使用真实记录呈现；只有用户主动移除已选项才删除对应 ID，取消选择器或再次确认不得静默缩小授权范围。

## 验收

按[质量验证](../../development/verification.md)执行前后端验证。重点覆盖普通 `admin` 角色创建与范围维护、已有授权保留、管理员账号仍拥有全部范围、草稿稳定选择与批量删除、业务投影、脏状态恢复、校验阻断、未知组织保留和查询错误阻断。Chrome 检查标准字段宽度与字号、明细紧凑控件、分区操作、顶部留白及组织选择交互。

## 默认角色

全局最多一个默认角色，也允许不设置。普通用户在当前有效任职组织中的有效角色为手工角色与默认角色的并集，同角色去重；管理员继续按独立身份规则授权。默认角色不创建任职、不改变组织切换资格，不绕过登录及用户安全校验。其数据范围按当前组织解释。

已有用户、新用户及已有手工角色的用户统一动态继承，不向用户角色表补写关系。切换或取消仅改变继承部分，原手工分配完整保留；因此清空手工角色不能撤销默认基础权限。默认角色权限或数据范围被修改也会影响所有普通用户。

列表通过“设为默认角色”设置或切换，选中当前默认角色时提供“取消默认角色”；使用独立 `sys:base:role:setDefault` 权限，确认明确全员影响，业务日志记录操作人及命令中的原角色、目标角色和版本。当前默认角色禁止直接删除，须先取消或切换。列表批量删除使用单事务命令，先检查整批目标并锁定默认配置；默认角色阻断、目标缺失或关联约束失败均整批回滚，不通过多个独立请求产生部分删除。用户角色分配页独立展示默认继承来源，仅手工分配进入保存内容。

配置使用数据库固定单例、行锁、版本校验和角色外键约束；切换与删除统一先锁配置，再锁角色。功能权限、角色编码、菜单、应用入口、固定应用、首页快捷入口和数据范围统一读取 `v_sys_user_effective_role`，授权查询不使用 MyBatis 缓存。提交后的后续鉴权请求读取新配置，已展示菜单和按钮在刷新权限后更新。

本次按明确要求将结构合入 V1、初始空配置及新权限合入 V2，不新增 V3；适用于空库安装，不自动更新既有开发库，不执行 repair 或清库。已有开发库的重建或受控转换需另行明确授权。验收覆盖无默认角色、已有用户、新用户、手工角色并集与去重、跨组织、切换和取消保留手工授权、非法任职不继承、默认角色删除阻断、并发旧版本拒绝及事务回滚。
