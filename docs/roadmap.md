# 项目路线图

本文只记录已经批准、尚未完成的项目级事项。详细设计进入架构文档或 ADR，实施过程和讨论进入 GitHub Issue；已完成事项从正文删除，通过 Git 历史和 Issue 追溯。

维护规则：

1. 每项只包含目标、剩余工作、完成条件和可选 Issue 链接。
2. 不记录每日进度、测试数量、构建体积或已经失效的实施步骤。
3. 未批准方案只放在 `proposals/`，不进入本路线图。
4. 正文保持精简；接近 150 行时必须清理或将执行细节迁入 Issue。

## 工程质量门禁收口

- 状态：进行中
- 目标：让主分支始终满足仓库内已经建立的质量门禁。
- 剩余工作：在 GitHub 仓库设置中启用主分支保护，将 `quality-gate` 设为必需检查。
- 完成条件：不通过质量门禁的 Pull Request 无法合并。

## 关键风险测试闭环

- 状态：进行中
- 目标：以精简、风险驱动的自动化测试保护安全、事务、状态、并发和关键前端生命周期。
- 剩余工作：核对数据库直接鉴权、凭据撤销与页面权限在真实请求链中的联动覆盖，并补齐完整纵向端到端场景。现有后端安全与前端请求错误单元测试不再作为待从零建立的能力，风险与验证入口见[质量验证](./development/verification.md#按风险增加验证)。
- 完成条件：每类真实高风险至少有一个稳定回归场景，且测试适合持续运行于 CI。

## 生产安全验证

- 状态：进行中
- 目标：验证 HttpOnly Cookie、CSRF 与浏览器安全策略在真实生产部署边界下有效。
- 剩余工作：在生产等价环境完成 Cookie 属性、CSRF、Origin、CSP、入口关闭、管理员初始凭据和浏览器加载验证。
- 完成条件：安全策略不影响正常登录和应用加载，非允许脚本与高风险入口受到预期限制。

## 外部可用性监控

- 状态：待部署环境落地
- 目标：覆盖 Smart Manage 集群整体不可达时无法自我告警的物理边界。
- 剩余工作：在生产入口配置独立 HTTP/进程探测和外部通知。
- 完成条件：应用全部停止或入口不可达时，仍能从 Smart Manage 集群之外发出通知。

## 采购申请端到端验收

- 状态：进行中
- 目标：将已经完成的人工纵向验收固化为可重复运行的核心端到端流程。
- 剩余工作：自动化登录、进入列表、新增保存、临时页签替换、详情回显、提交只读和并发冲突流程。
- 完成条件：端到端流程可重复执行，结论与现有后端和前端风险测试一致。

在本项完成前，不进入多业务模块并行铺量；后续业务扩展仍应一次只增加一个聚合，并遵循[新增业务聚合检查清单](./development/business-aggregate-checklist.md)。
