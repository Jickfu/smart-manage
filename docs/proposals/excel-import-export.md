## 状态与现行入口

首个用户导入、采购申请导出闭环已有实现；本文保留设计理由与后续阶段条件，不作为生效规则，也不表示全部后续能力完成。

- 用户匹配、导入模式、批次事务和一次性凭据见[用户管理](../domains/sys/base/user.md)。

## 设计理由

平台负责 Excel 文件格式、安全限制、结果和文件生命周期；领域模块保留字段、引用解析、权限、数据范围、校验和事务语义。实体、表名、Mapper 或 SQL 不能表达这些业务边界，因此不建设万能导入导出。

数据交换制品与业务附件共享物理存储适配，但其所有者授权、过期和一次性下载语义不同，不能复用附件关系模型。凭据制品与用户写入采用相同事务单位，避免数据写入与凭据交付脱节；物理存储无法加入数据库事务，需保留补偿与结果不确定时的默认拒绝语义，具体协议由上述现行文档维护。

首版选择有容量硬限制的同步读写和严格表头，避免在没有容量证据或兼容需求时提前引入异步编排及模板版本管理。前端公共层只提供交互机制，业务模式与模板契约仍由领域适配组件负责。

## 保留的方案细节

以下保留尚未被现行文档完整覆盖的设计细节，供追溯和核对实现；不因保留在提案中升级为生效规则。具体实现入口为 `sm.domain.sys.base.fileartifact` 和 `sm.system.excel`。

### 文件制品

数据交换文件不是业务附件。制品至少记录用途、所有者、对象键、存储类型、原始名称、MIME、大小、状态、过期时间和下载次数。对象前缀由受控用途产生：

```text
data-exchange/import/source
data-exchange/import/error
data-exchange/import/credential
data-exchange/export/result
```

一次性凭据制品下载前先原子声明为 `DOWNLOADING`；服务端完整传输后进入待删除状态，只有打开或传输失败才释放回 `ACTIVE`。完整传输后的状态完成操作失败时保留 `DOWNLOADING`，不得在结果不确定时重新开放一次性秘密；超过 1 小时仍未完成的一次性凭据下载声明按 fail-closed 原则进入 `PENDING_DELETE`，普通制品才恢复 `ACTIVE`。物理删除失败由集群清理任务幂等重试。其他结果按过期时间清理。下载前必须重新校验所有者或管理员授权。

### 模板与安全

- 首版只接受 `.xlsx`，拒绝 `.xls`、`.xlsm`、外部链接和公式业务输入。
- 首版以严格表头作为模板契约；表头变化必须重新下载模板，后续发生兼容版本并存需求时再引入 `templateVersion`。
- Excel 使用业务编码表达组织等引用，不暴露数据库 ID。
- 同时限制文件大小、Sheet 数、行列数、单元格长度和压缩展开规模。
- 普通文本导出统一防护 `= + - @` 公式注入。
- 日志不得记录文件正文、整行数据、密码或一次性凭据。

## 后续阶段条件

- 只有真实容量证明需要时，再设计持久异步任务、Dispatcher、进度、取消和“我的任务”；当前同步闭环不代表这些能力已实现。
- 不为每次请求动态创建 Quartz 任务定义。
- 出现模板兼容版本并存需求时，再引入 `templateVersion`；不能仅因存在本提案就预建版本框架。

上述后续事项仍需按实际需求明确设计与验收边界，不能直接作为已批准实施任务。
