# Excel 导入导出架构方案

## 状态

已批准并进入首个纵向闭环实现。稳定结论同步进入对应架构和领域文档；本文保留完整设计背景与后续阶段边界。

## 定位

Excel 导入导出是 Smart Manage 的平台基础能力。平台负责文件格式、安全、运行结果和文件生命周期，业务模块保留字段、权限、数据范围、引用解析、校验和事务语义。禁止通过实体、表名、Mapper 或 SQL 自动生成万能导入导出。

## 分层

```text
领域模块（导入/导出业务语义）
  -> 系统数据交换机制（结果、错误和制品生命周期）
    -> Excel 基础设施（Apache Fesod）
      -> FileStorageService（Local / FTP / S3）
```

- `sm.system.excel` 隔离 Fesod 类型；首版采用有容量硬限制的同步内存读写，负责 `.xlsx` 结构限制和公式注入防护。
- 领域模块定义自己的 ImportRow、ExportRow、权限、校验与 TxService。
- `sm.system.storage` 使用 `FileStoragePurpose` 管理稳定对象前缀，同时支持上传文件和服务端生成流。
- 附件与数据交换制品共享物理存储适配，不共享授权和生命周期模型。
- 前端通过通用数据交换弹框、文件下载工具和制品导出 Hook 复用交互机制；领域适配组件提供业务文案和命令，列表页不承载导入流程状态。

## 首个闭环

- 用户导入：以创建后不可修改的 `username` 为匹配键，支持 `CREATE_ONLY`、`UPDATE_ONLY`、`UPSERT`，并支持 `ATOMIC`、`BATCH`。
- 新增用户由系统生成随机初始密码，数据库只保存 Argon2 哈希；明文只进入短期、一次性下载的结果制品。
- 用户更新不得修改 username、密码、角色或头像；邮箱变更恢复未验证状态；任职按 `组织编码:职位` 完整替换。
- 采购申请导出：支持选中记录和当前筛选结果，服务端重新执行权限与 DataScope。

## 文件制品

数据交换文件不是业务附件。制品至少记录用途、所有者、对象键、存储类型、原始名称、MIME、大小、状态、过期时间和下载次数。对象前缀由受控用途产生：

```text
data-exchange/import/source
data-exchange/import/error
data-exchange/import/credential
data-exchange/export/result
```

一次性凭据制品下载前先原子声明为 `DOWNLOADING`；服务端完整传输后进入待删除状态，只有打开或传输失败才释放回 `ACTIVE`。完整传输后的状态完成操作失败时保留 `DOWNLOADING`，不得在结果不确定时重新开放一次性秘密；超过 1 小时的下载声明才按中断任务恢复。物理删除失败由集群清理任务幂等重试。其他结果按过期时间清理。下载前必须重新校验所有者或管理员授权。

## 模板与安全

- 首版只接受 `.xlsx`，拒绝 `.xls`、`.xlsm`、外部链接和公式业务输入。
- 首版以严格表头作为模板契约；表头变化必须重新下载模板，后续发生兼容版本并存需求时再引入 `templateVersion`。
- Excel 使用业务编码表达组织等引用，不暴露数据库 ID。
- 同时限制文件大小、Sheet 数、行列数、单元格长度和压缩展开规模。
- 普通文本导出统一防护 `= + - @` 公式注入。
- 日志不得记录文件正文、整行数据、密码或一次性凭据。

## 事务

- 所有模式均先完成文件结构、字段、引用和业务预校验，再写入。
- `ATOMIC`：单文件事务，任一冲突整体回滚。
- `BATCH`：固定批次短事务；每批原子，允许 `PARTIAL_SUCCESS`，错误报告明确成功和失败范围。
- 凭据制品与数据事务采用相同单位：`ATOMIC` 整个文件对应一个制品，`BATCH` 每个成功批次对应一个制品。物理对象先写入存储，用户数据与制品元数据在同一数据库事务登记；事务失败补偿删除物理对象。
- 数据库唯一约束与乐观锁仍是并发写入最终保障；预校验不能替代事务内复核。

## 后续阶段

首个闭环允许同步执行，但必须受容量硬限制。真实容量证明需要后，再新增持久异步任务、Dispatcher、进度、取消和“我的任务”；不得为每次请求动态创建 Quartz 任务定义。
