# 待议设计建议

本提案只维护尚未采纳的通用设计选择，不是开发门禁。正式要求见[前端规范](../../design/README.md)和[移动端规范](../../mobile/README.md)；已采纳内容不在本页重复定义。

## 基础视觉与可访问性

| 待议项 | 选择方向 | 采纳前需要核对 |
| --- | --- | --- |
| 辅助状态表达 | 用文字、图形和名称辅助颜色 | 与领域状态协议、现有控件可访问名称的关系 |
| 字体与层级 | 基于项目主题比较中文、拉丁字母、数字与长文本 | 最终字体回退、缩放、行高与截断，不以静态字体名保证一致 |
| 阴影、图标与动效 | 用最少层级表达覆盖、分区与反馈 | 优先原生主题能力，避免装饰性精细度造成私有覆盖 |
| 键盘与读屏 | 焦点可达、名称明确、关闭后恢复 | 具体组件与任务的实测，不把一项 aria-label 等同于完整体验 |
| 对比度目标 | 普通文本可评估 4.5:1、大文本 3:1、必要非文本线索 3:1 | 按真实前景/背景和文本尺寸测量；尚未作为全项目硬目标 |

对比度定义参见 [W3C 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)和[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。候选目标不代表当前全部主题组合已经达标。

## 桌面交互

复杂筛选、密集列表、特殊媒体字段以及新组件组合，应按实际任务评估信息优先级、长内容、输入恢复和空间。现有公共组件的使用契约仍归[页面指南](../../development/frontend-page-guide.md)，不在提案维护第二份组件百科、API 或验收制度。

有实际能力缺口时，再比较原生能力、有限扩展和替代布局；不因第三方组件目录中存在某项能力就要求底座全部实现。

## 移动端设计

下列数值仅为手机浏览器设计起点，须在目标小程序平台与真机确定后评审；不能直接换算为小程序逻辑单位。

| 项目 | 候选起点 |
| --- | --- |
| 主标题 | 18px / 28px 行高 |
| 分区标题 | 16px / 24px 行高 |
| 正文与输入 | 16px / 24px 行高 |
| 密集内容 | 14px / 20px 行高 |
| 次级信息 | 12px / 16px 或 14px / 20px，不用于关键数据 |
| 侧边距 | 可从 12px 试样，按设备与任务校准 |
| 点击区域 | 可从约 44×44 CSS px 或整行交互评估 |

底部命令、筛选与选择、键盘避让、固定区域和手势策略随真实任务设计，不整套移植桌面布局。正式共通要求与平台接入边界只在[移动端规范](../../mobile/README.md)维护。

## 图表细节与扩展

配色、趋势、完整数据与异常表达遵守[图表规范](../../design/charts.md)，可查看[通用示例](../../design/chart-examples.md)。下列内容仍需按任务明确：

- 轴、图例、提示、标记密度和具体尺寸；示例的 2px/6px 不成为全图统一值。
- 加载、无记录、失败、旧数据及权限状态的布局形式；请求与权限语义继续引用现有架构。
- 连续和发散配色的数值映射、中点、图例与对比度。
- 复杂图型、地图、实时数据、联动与导出的实际需求、数据规模和维护成本。

选型以业务问题为依据：类别比较可用柱/条形，有序趋势可用折线，同总体构成可用饼/环形，明确目标与量程的单指标可用仪表盘。其它图型有真实需求再评审，不为填满页面或扩大组件数量而引入。
