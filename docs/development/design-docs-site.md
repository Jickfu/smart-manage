# 开发规范站维护

`tools/design-docs` 独立构建规范站，直接读取仓库 Markdown；不复制正文，不进入业务应用依赖、菜单或构建。安装、预览、构建和验证命令统一维护在[质量验证](./verification.md#文档浏览入口)。

## 内容来源与职责

| 来源 | 展示职责 |
| --- | --- |
| `docs/design/` | 前端规范与通用示例 |
| `docs/backend/` 及所引用的架构、开发文档 | 后端规范入口和权威正文 |
| `docs/mobile/` | 移动端共通规范与平台接入边界 |
| 协作、模块指南与质量正文 | 开发人员与 Agent 的任务阅读路径 |
| 明确收录的设计提案 | 待议选择，不作为正式要求 |
| 其它正常项目文档 | 按原有架构、开发或领域职责使用 |

收录与分类由工具中的 `lib/content.mjs` 维护，导航只组织链接，不重新定义规则。提案默认不进入页面与搜索，仅明确收录的设计建议例外。发布到外部前审查内容范围和受众，不能把“可以构建”当作“全部内容可以公开”的结论。

## 链接与搜索

站内 Markdown 引用转换为静态路径，章节锚点沿用仓库规则。相对源码、仓库外文件与未收录文档显示为“仓库引用”，不导出源码或生成死链接；原始引用仍由仓库文档检查校验。

保持静态资源、站内链接和锚点检查，不通过全局忽略错误掩盖缺失文件。调整来源、路由或提案范围时，验证已收录页面、未收录材料和仓库引用的不同处理。

搜索在本地浏览器执行，支持中文词和完整规则编号；内容范围跟随规范与指定阅读入口，普通业务文档不自动混入规范搜索。不接入外部搜索、业务 API、遥测或第三方字体。

## 构建与依赖

工具拥有独立 package 与锁定文件；Vue、VitePress 和示例 ECharts 仅用于文档工具。依赖版本以工具 package 和 lock 为准，不与业务应用同步强升。

默认预览只绑定回环地址；产物位于 `tools/design-docs/dist/`，通过静态 HTTP 服务使用。`SM_DESIGN_DOCS_BASE` 指定 `/目录/` 形式的路径前缀，不是服务地址或凭据。缓存、临时目录和 dist 不提交，修改原始 Markdown 后重新构建，不手工补产物。

## 图表示例

[图表示例](../design/chart-examples.md)使用异步加载的 Vue 组件、公开 ECharts option 和 SVGRenderer；实例在卸载时释放，容器变化时 resize。固定数据与状态只演示规范，不对外提供业务组件或接口。

示例不能成为业务应用依赖，也不能因展示某个状态或图型就改变底座能力。组件和工具配置修改执行文档专用检查；实际业务代码变更按其所属质量要求执行。
