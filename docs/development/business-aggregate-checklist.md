# 新增业务聚合检查清单

本清单只将聚合特有风险转换为验收项，不作为独立规则来源。模块分类和接入步骤见[模块开发指南](./module-development-guide.md)，事务与数据契约见[后端架构](../architecture/backend.md)，访问边界见[安全架构](../architecture/security.md)及[数据权限](../architecture/data-permission.md)，页面职责和生命周期见[前端架构](../architecture/frontend.md)。是否启动新聚合仍遵守[项目路线图](../roadmap.md)的阶段门槛。

## 聚合模型与命令

- 主单具有明确业务身份，单据继承 `BaseBillEntity`，以 `org_id` 表达所属组织；申请人、负责人等角色由具体业务定义。
- 明细使用 `*Entry`，不建立独立写入口；即使没有明细，主从接口仍返回 `entries: []`。
- 可修改聚合包含 `version`，修改、提交和删除同时校验 ID、数据库状态和版本。
- `save` 区分新增与暂存修改，非暂存状态不能普通保存。
- `submit` 接收当前完整聚合，在同一事务保存并推进合法状态；新增允许直接提交，不要求先保存。

## 事务与并发验收

- 主单、明细由同一个事务边界写入；任一写入失败整体回滚。
- 删除主单前显式删除明细，不依赖数据库级联删除。
- 覆盖新增保存、暂存修改、新增直接提交和已有单据提交。
- 覆盖非法状态、过期 version 的修改/提交/删除，以及原子更新条件不匹配时的并发冲突。
- 按[质量验证](./verification.md#真实-postgresql-验证)触发真实数据库测试，不能用 Mock 或普通单元测试证明锁和事务行为。

## 对象级授权与通用资源

- 数据范围公共能力已经生效；新聚合必须明确归属字段，显式注册支持 DataScope 的资源及操作，并在查询和对象命令中落实领域解释。
- 列表过滤不能替代详情、修改、删除、提交和附件的对象级授权；未接入资源不得宣称具备组织级或行级隔离，接入限制遵守[数据权限](../architecture/data-permission.md)。
- 使用附件等通用资源时，在模块内注册稳定资源类型和授权策略；不使用时不增加空注册。
- 附件策略区分读取、绑定、解除和删除，组合实际业务角色、数据范围和单据状态；未知类型或缺少归属默认拒绝。
- 覆盖跨用户、跨组织、跨单据、非法资源类型的越权，以及临时附件所有权和正式附件继承单据权限。

## 聚合页面验收

- 新增保存后临时页签替换为真实单据页签，并重新查询详情回显。
- 已提交等只读状态进入 `VIEW`，不能普通保存。
- 新增、编辑均有脏数据关闭保护；主从明细及 Form 外部编辑共同参与脏状态和保存转换。
- 命令完成后的缓存失效、操作日志及权限边界符合对应架构；页面布局和明细操作区按[前端页面指南](./frontend-page-guide.md#编辑页)核对。

具体验证命令和风险触发条件统一见[质量验证](./verification.md)，不为字段访问器或简单转换增加低价值测试。
