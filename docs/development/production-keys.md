# 生产密钥生成与部署

本文用于二开项目的新环境初始化、备份恢复与密钥变更。密钥配置与加密边界分别以[配置说明](./configuration.md)和[安全架构](../architecture/security.md)为准。

## 需要准备多少密钥

平台固定需要 **一对 SM2 公私钥和一份部署级 SM4 密钥，共三个配置值**。同一环境的全部后端实例使用同一组值；开发、测试、不同客户的独立生产环境分别生成。

| 材料                   | 格式与配置入口                                                | 用途与生成位置                                     |
| ---------------------- | ------------------------------------------------------------- | -------------------------------------------------- |
| SM2 私钥               | 32 字节十六进制，`SMART_MANAGE_SM2_PRIVATE_KEY`               | 后端解密登录、改密及身份复核中的密码；离线工具生成 |
| SM2 公钥               | 带 `04` 前缀的 65 字节非压缩点，`SMART_MANAGE_SM2_PUBLIC_KEY` | 浏览器加密密码；与私钥配对生成，允许公开           |
| 部署级 SM4 密钥        | 16 字节的 Base64，`SMART_MANAGE_SM4_KEY`                      | 加密数据库敏感内容；离线工具生成                   |
| OpenAPI 签名密钥       | 每份凭据 32 字节，Base64                                      | 管理端创建凭据时生成，用于 HMAC-SHA256             |
| OpenAPI 请求和响应密钥 | 每份加密凭据各一份；AES 各 32 字节，SM4 各 16 字节，Base64    | 管理端创建凭据时独立生成；选择 `NONE` 时不生成     |

OpenAPI 没有额外的公私钥对。其 `keyId` 是凭据标识，不是密钥。每份凭据增加一份或三份对称密钥，均由部署级 SM4 加密后保存。生成和轮换流程见[OpenAPI 凭据包](../domains/sys/base/openapi-platform.md#凭据包)。

## 一条命令生成新环境密钥

需要 Node.js 22+，且运行时 OpenSSL 支持 SM2。无需安装 npm 依赖、启动后端或连接数据库。从仓库根目录执行，目标目录必须事先存在，建议使用仓库外的部署配置目录：

```powershell
node scripts/generate-deployment-keys.mjs --output E:/deploy/customer-a/config/deployment-keys.env
```

Linux 使用同一命令与对应路径：

```bash
node scripts/generate-deployment-keys.mjs --output /opt/customer-a/config/deployment-keys.env
```

工具仅生成上述三个平台配置值，**不生成 OpenAPI 凭据、不修改源码、不替换现有配置、不迁移数据库**。文件已存在时拒绝覆盖。终端只显示文件路径，不显示私钥或 SM4 密钥。

Linux/macOS 文件创建权限为 `0600`；Windows 在写入前取消继承 ACL，仅授权当前用户。权限设置失败则停止并删除本次未完成文件。交付服务运行账号时，应由管理员显式授权该账号读取，保留最小访问范围。

生成文件是 `NAME=value` 配置材料，**Spring Boot 不会自动读取 `.env` 文件**。请选择一种接入方式：

- 通过服务管理器、容器编排或密钥管理设施，将文件内三个变量注入 Java 进程环境。
- 将值填入仓库外的外部 YAML：`smart-manage.system.security.sm2.js.private-key`、`smart-manage.system.security.sm2.js.public-key` 和 `smart-manage.system.security.sm4.key-base64`。外部配置加载方式见[生产环境](./configuration.md#生产环境)。

不要在命令行参数中填写私钥，不要提交生成文件或放入前端目录、镜像和应用日志。工具失败时检查目标目录、权限和 Node.js 的 SM2 支持，不使用开发密钥兜底。

## 新环境上线清单

1. 使用 `prod` Profile，在独立环境首次初始化前生成密钥，替换全部公开开发配置。启动校验会检查格式及 SM2 公私钥匹配，但不能替代运维确认“未复用开发密钥”。
2. 所有后端实例配置相同的 SM2 密钥对与 SM4 密钥；为不同实例配置不同的实例 ID。
3. 登录页在每次提交密码前通过 `GET /sys/base/login/password/publicKey` 获取当前公钥。接口与请求均禁用缓存；公钥缺失、格式错误、曲线点无效或网络失败时阻止密码提交。无需修改 `login.html`，无需因换密钥修改 CSP 摘要。
4. 保持 HTTPS、生产 Cookie 与代理配置；SM2 不能替代 TLS。代理不得强制缓存公钥接口。
5. 将密钥放入受控备份，与数据库备份建立可追溯对应关系。SM4 密钥丢失后不能从数据库密文恢复。
6. 在生产环境重新创建 OpenAPI 凭据并交付对应调用方；创建成功只显示一次，关闭后不能再次读取。不要沿用测试凭据。
7. 替换数据库和 Redis 口令、初始管理员密码；在相应管理页面配置生产 SMTP 密码、S3 Access Key/Secret Key 或 FTP 凭据。HTTPS 证书及私钥由证书签发和部署设施管理，不由本工具生成。
8. 验证普通登录、首次改密、邮箱找回、存储访问、邮件发送，以及已启用的 OpenAPI 签名和双向解密。多实例验证必须覆盖各个节点。

用户密码哈希、会话 Token、CSRF Token、验证码票据、GCM IV 和 nonce 不属于手工部署密钥，由相应流程自动维护。不要修改数据库中的密码哈希来“替换加密密钥”。

## 已有数据库不能按新环境处理

**升级应用、重启实例和恢复备份时，通常应保留原密钥，不能每次部署都运行生成工具替换配置。**

| 变更对象     | 影响与操作要求                                                                                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SM2 密钥对   | 只用于密码传输，不要求重写用户密码哈希。安排维护窗口协调所有节点切换；当前不支持新旧私钥并行解密，切换中的在途提交可能失败，需用户重试。旧版登录页若仍内置开发公钥，必须先更新前端制品 |
| 部署级 SM4   | 涉及 S3 Secret Key、FTP 密码、SMTP 密码、尚未清除的敏感邮件正文、OpenAPI 签名/请求/响应密钥密文。直接替换会使这些内容无法解密                                                          |
| OpenAPI 凭据 | 在管理端创建新凭据，安全交付并切换调用方，验证成功后停用旧凭据；与平台 SM2 密钥无关                                                                                                    |

目前不提供部署级 SM4 的自动轮换工具，也没有多密钥版本读取能力。密文前缀 `sm4-gcm:v1:` 表示格式版本，**不是密钥版本号**。确需轮换时，须另行制定受控迁移：备份数据库和旧密钥、停止相关读写及邮件任务、完整识别现存密文、用旧密钥解密后以新密钥重加密、同步切换全部实例、验证并保留成套回滚材料。不能仅替换配置，也不能仅重填存储密码而遗漏 OpenAPI 或邮件数据。

从开发/测试数据库复制到生产同样属于存量密文迁移，不是空库初始化。按迁移方案处理已有密文后才能使用新密钥；备份恢复必须使用与备份密文匹配的密钥。

## 验证生成工具

在仓库根目录执行，使用系统临时目录生成一次性测试密钥并清理，不输出密钥内容：

```bash
node --test scripts/generate-deployment-keys.test.mjs
```

该测试检查格式、公私钥匹配、独立随机生成、文件权限及拒绝覆盖，并接入 CI；不能替代目标环境的部署验收。
