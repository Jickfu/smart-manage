# 模块开发指南

本指南用于新增或显著扩展 Smart Manage 业务模块。它负责把仓库架构约束转化为可执行的开发流程；根目录和前后端 `AGENTS.md` 仍是强制规则来源，领域文档仍是具体业务语义来源。

小范围缺陷修复、纯重命名或不改变模块边界的局部调整不要求完整执行本流程，但仍必须遵守相关 `AGENTS.md` 和验证规则。

## 1. 实现前基线

在写代码前必须从仓库确认并记录以下内容：

| 项目       | 必须明确的结果                                             |
| ---------- | ---------------------------------------------------------- |
| 需求边界   | 本次实现什么、明确不实现什么、可验证的完成标准             |
| 模块类型   | 业务聚合、主数据、配置、查询记录、监控/控制台或公共能力    |
| 归属       | `{领域}/{应用}/{模块}`、是否属于系统内核、允许依赖的方向   |
| 稳定身份   | `featureKey`、页面键、权限码、业务资源类型、编号引用键等   |
| 页面形态   | `LIST + EDIT`、单独 `CUSTOM`，或确有依据的其他组合         |
| 状态与命令 | 保存、提交、启停、封存、取消、重试等命令及其最小参数       |
| 数据边界   | 组织归属、对象级访问、敏感字段、凭据、并发版本和保留周期   |
| 参考实现   | 从模块样板目录选择的后端、前端和测试样板；不能只凭记忆实现 |
| 验证       | 编译、测试、静态检查、生成器、迁移和必要的浏览器验收       |

如果其中任一未明确项会改变架构方向、数据安全、外部状态或形成明显不同的产品结果，必须先询问；其余内容优先通过代码、迁移和当前文档自行核实。

## 2. 模块分类和默认形态

### 2.1 业务聚合

具有独立业务身份、状态流转或主从数据的单据属于业务聚合。默认采用：

- 后端公开 `*Service` 加包级 `*TxService`；
- Entity、Form、VO、Mapper 和纯字段 Converter；
- `listPage`、`detail`、`createNewData`、`save`、`submit`、`delete` 等标准语义；
- 前端 `LIST + EDIT`、Query Key Factory、领域 Mutation 和页签生命周期；
- 即使当前没有明细，主从聚合的前后端模型仍使用 `entries: []` 表达稳定聚合结构；
- 可修改聚合使用 `version`，主从数据在同一事务内写入；
- 同时执行[业务聚合检查清单](./business-aggregate-checklist.md)。

### 2.2 主数据或独立配置

具有独立编码、列表、新增、编辑和详情语义的主数据或配置，默认采用独立 `LIST + EDIT` 页面。禁止为了少建一个页面，把列表与编辑表单拼进同一个 `CUSTOM` 页面。

配置中的密码、令牌、私钥或授权码不属于普通参数：必须遵守敏感配置和数据脱敏规范，详情只返回“是否已配置”等安全状态。

### 2.3 查询记录

日志、发送记录、执行记录等不可随意修改的事实数据，通常采用 `LIST` 加独立只读详情页签。详情不能用 Drawer 代替工作台页面；重新发送、取消等动作应建立专用命令，不能改写历史记录。

### 2.4 监控和控制台

只有布局、实时交互或信息密度确实无法由通用列表/编辑模型表达时才使用 `CUSTOM`。CUSTOM 不是绕过页面生命周期、权限、查询状态或视觉规范的捷径。

### 2.5 公共能力

出现第二个真实使用方并且语义稳定后，才考虑提取领域或应用 `common` 能力。公共层不得吸收具体业务语义，也不得通过扫描、命名或路径推断稳定业务身份。

## 3. 后端实现顺序

1. 确认领域文档、安全边界、数据归属和状态机。
2. 设计新增 Flyway 迁移；系统内置 Feature、权限、菜单和必要初始化数据一并通过迁移维护。
3. 定义 Entity、Form、VO 和权限常量，明确 ID、`version`、引用对象及敏感字段的 JSON 边界。
4. 建立 Mapper 和纯字段 Converter；关联查询应批量加载或由 MyBatis 直接投影。
5. 按查询管理、当前用户资料、认证或授权等明确业务职责建立一个或多个公开 `*Service`，分别承担对应查询、命令入口、权限补充校验、业务组装和 `@BizLog`；不得为维持单一 Service 而混合不同业务语义。
6. 将事务写入放入同模块包级 `*TxService`，事务内重新校验存在性、状态、版本和唯一性。
   一个业务动作只由一个 TxService 持有事务；多个事务入口复用同一写能力时，抽取 package-private、无事务注解的 `*Writer`。跨模块事务组合使用能力提供方发布的最小事务参与 Contract，不直接依赖其他模块的 TxService、Writer 或 Mapper。
7. Controller 只依赖公开 Service，统一使用 `Result<T>`，权限注解引用模块权限常量。
8. 为状态、事务、并发、安全、外部副作用和架构边界补充风险驱动测试。

### 后端关键决策

- `save` 只保存新增或暂存修改；`submit` 保存完整聚合并推进状态。
- 启用、停用、封存等独立状态必须使用专用命令，只接收 ID、并发版本和目标状态等最小参数；不得混入保存 Form。
- 详情中的实体引用返回引用对象，默认包含 `id`、`number`、`name`；保存只提交外键 ID。
- 外部 HTTP、SMTP、对象存储等副作用原则上不在数据库事务中执行，并定义超时、失败和补偿语义。
- 具有独立业务身份的主数据和单据使用 `number`；通用说明性字段使用 `description`。

## 4. 前端实现顺序

1. 根据模块类型选择 `LIST + EDIT` 或 `CUSTOM`，并从[模块样板目录](./module-pattern-catalog.md)选择最接近的页面。
2. 定义 `types.ts`、`api.ts`、`permissions.ts`、`queryKeys.ts` 和 `pageRegistration.ts`；前端 ID 一律为 `string`。业务单据 Query Key Factory 至少包含 `all`、`lists`、`list(params)`、`details` 和 `detail(id)`。
3. 页面注册显式声明稳定 `featureKey`，同一功能的 LIST、EDIT、CUSTOM 页面共享该身份。
4. 列表优先使用 `ListPage` 和 `useListPageQuery`；编辑优先使用 `EditPage`；实体引用优先复用或新增 `use*RefSelector`。
5. 领域页面负责状态流转、Mutation、缓存失效、详情回显和页签替换，不在页面壳层重复实现通用 loading 与错误提示。
6. 删除、清空、覆盖等操作确认通过 `useOperationConfirm` 声明风险类型；保存、提交、审核等结果通过 `useOperationFeedback` 展示，禁止直接调用 Ant Design 的 `Modal.confirm`、`Popconfirm` 或 `message.*`。
7. 完成列表选择、命令启用条件、编辑/查看模式、脏数据保护和首次保存后的临时页签替换。
8. 按同类页面完成视觉核对，再执行生成器、静态检查、测试和构建。

### 应用首页

- 新应用只有在存在明确的应用级快捷入口、业务摘要、待办、趋势或运行状态时才实现专属首页；首页组件放在对应领域应用的 `home/` 目录，并通过 `pages/workbench/applicationHomeRegistry.ts` 注册。没有专属内容时使用工作台默认首页，不虚构业务能力。
- 卡片行统一使用 `domain/common/home/HomeCardGrid`。该容器固定为四列轨道，卡片通过 `sm-home-card-span-1`、`sm-home-card-span-2`、`sm-home-card-span-3` 或 `sm-home-card-span-4` 表达等分、`1:3`、`2:2`、`3:1` 和整行布局；领域页面不得复制网格 CSS。
- 屏幕变窄时必须保持同一行的列数和跨列比例，由 `HomeCardGrid` 提供行内横向滚动，不得通过媒体查询把卡片自动折到下一行。首页整体内容超出视口时仍由首页容器纵向滚动；卡片内部存在固定高度列表时由卡片内部滚动。
- 文字指标卡的标题、主值和说明默认水平、垂直居中；同一卡片包含多个并列指标时使用稳定分割线区分。图表、表格和拓扑卡按内容特征布局，不强制套用文字指标卡结构。
- 首页优先展示权限和数据范围内的真实业务数据；暂时没有安全、稳定的聚合接口时可以使用示例卡片，但每张示例卡必须明确显示“示例”，不得与真实数据混淆。
- `QuickLaunchCard` 是可选的当前用户偏好能力，不是应用首页必备区块。只有应用菜单较多且用户确有高频快捷发起需求时才接入；不需要时直接省略，不渲染占位。系统首页是否使用该能力由系统首页需求决定。
- 没有额外操作、筛选或状态信息时，不在应用首页顶部重复展示应用名称或说明性头部。

### 列表和命令

- 默认使用复选框；单记录命令在恰好选中一条时启用。只有业务语义天然互斥且无法用命令启用条件表达时才使用单选。
- 默认不增加“操作”列。编辑或查看优先使用可点击的 `number` 等稳定业务标识，其他命令集中在页面操作区。
- 可由 `columnFeatures` 表达的字段筛选、枚举筛选和排序不得通过 `filterContent` 重复实现。
- 至少保留一个未设置 `width` 的业务列吸收剩余空间。
- 左树必须具有符合业务语义的根节点并默认展开；组织树等已有稳定语义的结构必须与现有页面保持一致，不得擅自增加“全部”等虚构层级。

### 编辑页

- 业务详情、记录详情和只读查看使用工作台通用编辑/查看页签；Drawer 只用于不形成独立页面的临时辅助操作。
- 标准字段、引用选择器和普通命令组成的表单必须使用 `EditPage`。
- `EditPage` 的全部正文卡片由调用方通过 `sections` 决定身份、顺序和内容，公共组件不得固定基本信息、明细、附件或其他业务分区。标准字段卡片复用 `editFormSection`；附件等通用能力提炼为组件或 Hook 后由领域页面显式组合，并通过通用的值转换和脏状态接口接入保存生命周期。
- `EditPage` 的明细区域或其他使用 `EditSectionCollapse` 的数据卡片需要提供新增、删除、排序等操作时，必须通过对应分区的 `extra` 将操作统一放置在标题栏右侧。表格通过选择列确定操作目标，禁止新增“操作”列，也不得将操作按钮散落在折叠面板内容区。只有存在明确的特殊交互要求时才允许偏离，并应说明原因。
- 表单内可编辑明细表格统一复用 `EditableDetailTable`：默认显示 `#` 序号列，并将 `36px` 复选框列和紧随其后的 `44px` 序号列固定在左侧；只有表格已提供具有明确业务含义的顺序列时才关闭默认序号列。点击复选框执行增量多选，点击行内其他区域收敛为当前行单选；编辑元素使用容器白色背景，普通行控件保持无边框，悬停或选中行显示与单元格保持约 `3px` 间距的控件边框，焦点和错误状态分别使用主色和错误色，`Switch` 不增加外围编辑框。`RefSelector` 等默认使用下边框的字段进入明细表后，由通用明细组件消除重复底边框，只保留当前交互状态所需且不被内部输入元素遮挡的一层完整控件边框。必填标识放在列头；校验失败时由页面提示并聚焦首个错误单元格，错误文案仅在该单元格聚焦时浮动展示，禁止使用会挤占表格高度的底部常驻错误区。业务列、动态控件和领域校验仍由领域组件维护。
- 基本身份字段放在“基本信息”；协议、连接、运行参数等领域配置放在独立面板，不把所有字段堆进一个分组。
- 启停、封存等状态不在编辑页展示，也不进入保存或提交类型；新增状态由后端给出安全初值。
- 通用说明性字段统一为 `description`，标签为“描述”。
- 新增保存后重新查询详情，并将临时页签替换为真实 ID 页签；保存后停留在当前页面。

### 表单字段布局

普通表单字段统一使用 `FormFieldGrid` 与 `FormFieldCell`；标准 `EditPage` 通过 `EditFormFields` 间接复用，手写字段保持以下结构：

```tsx
<FormFieldGrid maxColumns={2}>
  <FormFieldCell columnSpan={2}>
    <Form.Item className="sm-edit-field-content">...</Form.Item>
  </FormFieldCell>
</FormFieldGrid>
```

- 页面默认四列上限，普通弹框使用 `maxColumns={2}`，窄参数弹框使用 `maxColumns={1}`；两列和单列容器整体居中，内部字段仍从左向右排列。
- `FormFieldCell` 默认占一列，使用 `columnSpan={2 | 3}` 或 `fullWidth` 跨列；`Form.Item` 必须是其直接子元素并使用 `sm-edit-field-content`。
- 字段宽度、间距、断点和跨列计算属于公共布局契约，领域页面不得直接拼装或覆盖内部 `sm-edit-*` 类；新布局需求应先确认边界再扩展公共组件。
- 头像、分区标题、提示和按钮区由外层布局组织；查询筛选器、隐藏字段、可编辑表格单元格、代码编辑器及专用控制台不套用字段容器。

### 实体引用选择

#### 适用范围

- 从已有实体集合中选择一条或多条记录，并用于表单引用、主从明细、关联关系、授权关系或分配结果时，统一使用 `RefSelector`。
- 该规则不受页面形态和入口位置影响，适用于 `EditPage`、列表页、CUSTOM 页面、明细卡片和操作按钮弹框。
- 优先由实体所属领域提供 `use*RefSelector`，集中定义候选查询、展示字段、选择模式和业务范围。

#### 标准交互

- 搜索框位于弹框标题栏右侧，候选数据使用服务端分页和关键字查询。
- 单选使用单选列，多选使用复选列；点击整行执行选择或取消，多选支持跨页保留和已选结果管理。
- 选择列、序号列和内容型业务列使用稳定宽度，并至少保留一个未设置宽度的业务列吸收剩余空间。
- 表格统一使用固定布局、文本省略和完整 flex 高度链。

#### 查询与缓存

- 影响候选范围的组织、排除集合和选择用途等上下文必须进入查询参数及稳定 `selectorKey`，避免候选数据串用。
- 已关联或不可选记录应由服务端排除；需要向用户解释不可选原因时，由选择器明确禁用并展示原因。

#### 结果边界

- 选择器确认后向领域页面返回实体对象，由领域页面合并表单或暂存关系；最终保存只提交实体 ID。
- 取消或关闭选择器不得修改页面暂存结果。
- 只有 `RefSelector` 无法表达真实业务交互时才扩展或自定义选择能力，并在实现基线中记录差异及原因。

### 弹框、表格和视觉

- 全局字号基线由 `smart-manage-web/src/styles/theme.ts` 统一维护：页面正文、表单标签、按钮及其他操作控件使用 `12px`，Input、InputNumber、Select、TreeSelect、Cascader、DatePicker、Mentions、ColorPicker 等可录入或选择控件的默认字段值使用 `14px`。`RefSelector`、`IconSelector` 等项目自定义输入控件必须与标准输入控件保持 `14px` 字段值；`EditableDetailTable` 是统一的紧凑输入边界，其单元格内标准及自定义输入控件统一使用 `12px`，不得由业务页面各自覆盖。其他 small 输入控件只有在经过验证的紧凑边界内才使用 `12px`。业务页面和公共组件不得为获得默认密度而重复声明 `font-size: 12px` 或 `font-size: var(--ant-font-size-sm)`，也不得通过局部 `ConfigProvider` 复制全局字号主题。
- CSS 中的显式字号只用于不能由全局主题表达的视觉语义，并在实现和评审时分为标题或产品骨架、图标尺寸、特殊展示内容三类；页面标题、应用级导航、内容页签、卡片或分区标题等按既有同类样板保留层级，图标字号不得当作正文覆盖清理，品牌文字、数据主值、代码编辑器等特殊展示必须由真实视觉需要驱动。无法归入上述类别的字号声明视为可疑项，应先核对同类页面和最终计算样式，不得直接新增。
- 新增或修改组件字号时，优先调整全局或对应 Ant Design 组件 token；只有局部语义确实不同且扩大主题影响范围不合理时才使用 CSS。清理重复覆盖后必须核对表单、表格、树、分页、弹层和自定义控件的最终计算字号，并确认标题层级、图标尺寸、行高、截断和垂直居中没有回归。
- 系统内所有 Ant Design 表格统一由全局 `Table` 主题令牌提供四档行背景：普通行白色、仅悬停行中性灰色、选中行极淡主题色、选中且悬停行稍深主题色。`ListPage`、`RefSelector`、可编辑明细表和业务弹框表格不得各自覆盖这些状态或增加斑马纹；领域状态确需着色时使用业务 `rowClassName`，并确保选择反馈仍可辨识。
- 业务表单、命令参数和复杂结果展示弹框默认使用 `AppModal`。
- 删除、清空、覆盖、提交等需要用户二次确认的操作统一通过 `useOperationConfirm` 调用，并显式选择 `delete`、`destructive`、`warning` 或 `normal` 风险类型。确认弹框由公共组件统一提供可拖动标题栏、风险色圆点、业务插画、`14px` 提示文案和底部按钮区；点击遮罩不得关闭。危险操作不得使用 Enter 确认，业务页面禁止直接使用 `Modal.confirm` 或 `Popconfirm`。
- 保存、提交、审核、删除、复制等操作结果统一通过 `useOperationFeedback` 展示，顶部反馈正文统一使用 `14px`。反馈分为 `success`、`warning`、`error`、`info`：成功使用绿色，可由用户修正的输入或业务状态问题使用黄色，网络、安全、系统及未知失败使用红色，中性说明使用蓝色。反馈默认自动关闭；只有确需用户持续查看时由调用方设置 `autoClose: false`，此时右侧显示关闭按钮。顶部最多保留三条；业务页面禁止直接调用 Ant Design `message.*`。
- 后端异常提示只允许按稳定错误码分类，不得根据错误文案判断级别。可修正业务错误码由公共策略集中维护，未登记错误默认按红色错误展示。
- `ListPage`、`EditPage`、`EditPageShell` 和 CUSTOM 页面自定义顶部操作区中的普通命令按钮统一使用 `primary`；删除、清空、强制执行等会造成数据丢失、不可逆变更或明显安全风险的命令使用 `danger`。
- 顶部操作区从左到右先放影响命令上下文的选择或配置控件，再放新增、保存、提交、执行等主要命令，然后放查看、复制、刷新等辅助命令，最后放删除、清空等危险命令。存在明确业务流程要求时可以调整，但必须保持相关命令相邻并说明原因。
- 业务弹框中的标准控件以通用编辑页为视觉基准，默认使用下边框控件和稳定列宽；特殊宽度必须由真实布局需要驱动。
- 未有明确需求时，按钮只显示文字，不添加图标。
- 表单字段校验由 Ant Design Form 负责；没有明确的外部不可信数据校验需求时，不引入重复校验模型。
- 页面内容区与工作台边界、同级卡片或块状容器保持 `10px` 间隔；使用通用壳层时不得重复叠加页面级 padding。
- 页面头部没有操作、筛选或状态内容时不渲染空占位。
- CUSTOM 页面中的数据表默认关闭表格内置底部分页，将分页放在所属卡片或区块右上角元信息区。
- 固定高度表格建立从容器到 `.ant-table-body` 的完整 flex 高度链，使横向滚动条固定在内容区底部；禁止用固定 `scroll.y` 撑出伪布局。
- TSX 中禁止 CSS 和内联 `style`；自定义类名以 `sm-` 开头。

## 5. 功能、权限、菜单和页面闭环

新增功能必须能从稳定身份追踪完整闭环：

```text
Feature(featureKey)
├── Permission(permission code)
├── Menu(componentKey + entry permission)
└── PageRegistration(componentKey + featureKey + pageType)
```

- Feature、内置权限和菜单通过新增 Flyway 迁移维护。
- Controller 使用模块权限常量；前端 `permissions.ts` 与后端权限语义一致。
- 菜单入口权限与目标页面必须属于同一 Feature。
- 禁止通过权限码前缀、菜单名称、目录或组件路径推断功能归属。
- 页面注册变更后必须重新生成注册表并确认无差异。
