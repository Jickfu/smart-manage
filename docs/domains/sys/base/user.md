# 用户管理

## 模块定位

用户模块维护系统账号、基础资料、启停状态、任职、角色关系以及认证和授权所需的用户侧业务规则。它属于 `sm.domain.sys` 系统管理业务领域，不属于 `sm.system` 系统内核；其他顶级 Domain 不得直接依赖用户 Service、Mapper、Entity、缓存或数据表。

## 公开职责

- `UserService` 负责后台用户管理、任职组装和启停命令。
- `UserImportService` 和 `UserExportService` 分别负责用户 Excel 导入与导出，数据交换职责不混入用户日常管理入口。
- `UserProfileService` 负责当前用户资料。
- 认证、凭据和授权使用各自职责明确的公开 Service，不通过用户管理 Service 暴露。
- 跨顶级 Domain 的业务引用只依赖 `sm.domain.sys.base.user.contract`。

## 跨领域用户引用

用户领域发布 `UserReferenceReader` 和 `UserReference` 作为最小只读 Contract。`UserReference` 只包含 `id`、`number`、`name` 和 `enabled`，不暴露用户名、联系方式、密码状态、任职、角色、权限或用户 Entity。

- `require` 要求用户存在，但允许返回已禁用用户，用于仍然有效的历史引用读取。
- `requireEnabled` 要求用户存在且启用，用于新增或修改单个业务引用。
- `findByIds` 批量返回仍然存在的用户，允许缺失，用于查询组装；结果按去重后的输入顺序排列。
- `requireEnabledByIds` 使用一次批量查询校验全部用户，任何用户不存在或禁用都整体失败。
- 空批量输入返回空结果；非空输入中的空用户 ID 属于参数错误。

通用的“可作为新业务引用”只表示用户存在且 `enabled=true`。任职、组织、角色、权限、管理员身份或调用者数据范围不隐式进入该 Contract，应由拥有相应语义的领域能力或具体业务用例校验。

业务实体默认只持久化用户 ID，查询时通过 Contract 组装当前引用信息。需要保留发生时姓名等历史快照时，由具体业务聚合显式建模；用户 Contract 不承诺历史快照，也不替代业务领域对用户删除后展示语义的设计。

## 数据边界

用户联系方式遵守[数据脱敏架构](../../../architecture/data-masking.md)，密码、验证码、令牌和其他凭据不得进入普通查询或跨领域 Contract。用户禁用、删除、邮箱变更和凭据重置后的数据库代际校验与会话失效遵守[安全架构](../../../architecture/security.md)。

## Excel 导入

用户导入以创建后不可修改的 `username` 为匹配键，工号不是导入定位键。支持仅新增、仅更新、新增或更新，以及全文件原子和分批提交两种事务模式。

- 新增用户由服务端生成随机初始密码并强制首次登录修改；明文只进入短期一次性结果制品，不进入模板、日志或普通接口结果。
- 更新不得修改 username、密码、角色或头像；任职按 `组织编码:职位` 表达，多项使用英文分号分隔、首项为主职，并整体替换；邮箱变化后恢复未验证状态。
- 导入同时要求独立权限和真实 `administrator` 身份，不能用普通用户保存权限代替。
- 文件完整预校验后才允许写入；批量模式按批次原子提交并生成明确错误报告。
- 全文件原子模式生成一个初始密码制品；批量模式中每个成功事务批次生成一个独立制品。凭据物理对象必须先准备成功，用户写入与制品登记随后在同一数据库事务提交，失败时补偿删除对象。
- 用户展示缓存刷新在数据库提交成功后执行；刷新失败形成独立警告，不得把已经提交的批次报告为写入失败。授权每次直接读库，安全字段变化由数据库触发器推进独立凭据代际，不依赖导入后的缓存清理。

## Excel 导出

用户管理提供两种导出布局，并统一使用当前查询条件和选中记录作为数据范围：

- 按完整模板导出：使用系统内置的固定“用户完整信息导出模板”，包含账号、基础资料、状态、任职和创建时间。
- 按导入模板导出：按用户导入列输出现有数据，可直接整理后再次导入；初始密码等凭据不进入文件。

两种用户导出均要求独立导出权限和真实 `administrator` 身份。服务端重新执行查询范围与结构化筛选，不信任前端当前页数据；单次最多导出 10000 个用户，结果作为 24 小时有效的数据交换制品保存。
