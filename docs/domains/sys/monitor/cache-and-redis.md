# 缓存监控

## 模块边界

- “缓存状态”只读展示 Redis 当前快照和当前应用节点的 JetCache 本统计周期指标；页面不得为了展示而创建缓存实例；
- “缓存管理”左树分为受控应用缓存和预登记基础设施缓存；不提供通用“其他 Redis Key”入口；
- 应用缓存只按统一目录登记的前缀执行受限 SCAN；基础设施缓存只能通过精确 Key 或稳定索引派生条目，禁止全库扫描；
- 缓存管理使用标准分页和关键字搜索，支持受限 Value 预览和顶部批量删除，不提供行内操作列；
- “清空全部应用缓存”只清理服务端明确登记的 JetCache 缓存，不等同于 `FLUSHDB`；
- 不提供 `KEYS *`、`FLUSHDB`、Value 修改或历史指标持久化；
- 业务正确性涉及的系统参数、基础资料选项、用户信息和 `userId + orgId` 授权快照使用 Redis REMOTE 缓存，写入后删除共享键；不得依赖请求回到原实例。界面配置包含短时对象存储签名 URL，每次从共享数据库读取并实时组装，不缓存签名结果。包含解密后存储凭据的文件配置不进入任何缓存。LOCAL 缓存仅允许用于可丢弃且允许节点间短暂不一致的数据；JetCache 统计始终属于当前应用节点，不得因缓存存储在 Redis 就表达为集群统计。
- 后端只公开 `CacheService` 作为缓存监控业务入口；Redis 原始命令封装在缓存模块内部的 `RedisCacheAccessor`，不得被 Controller 或其他领域直接调用；

## 缓存命名与归属

- 业务应用创建的 JetCache 缓存名和自有 Redis Key 必须使用 `{domainNumber}:{appNumber}:{resource}` 前缀，例如系统服务领域下系统管理应用的系统参数缓存使用 `sys:base:sys-param`；
- Redis 条目按物理 Key 识别归属；LOCAL 条目按已登记的 `cacheName` 识别归属，逻辑 Key 不承担领域和应用分类语义；
- 领域编码和应用编码来自系统领域与应用目录，禁止为缓存管理另建硬编码映射；
- 框架、安全组件或第三方缓存不强制伪装成业务应用缓存，不能匹配已登记应用时统一进入“其他缓存”；
- 新增受管应用缓存时必须补充目录与命名测试，未登记缓存不得出现在管理界面。
- 应用缓存名称、类型、TTL、敏感属性和说明必须来自唯一缓存定义目录；注解、主动失效和运维页面禁止各自维护重复定义。

## 安全边界

- 缓存条目查询、Value 预览、删除和应用缓存清理同时要求对应功能授权和 `administrator` 身份；
- Sa-Token、验证码、密码修改票据和临时代登录凭证只在左树登记类别及 Key 规则，不扫描、不枚举、不返回 Value；
- 已登记且非敏感的 JetCache 应用缓存通过其受控缓存定义解码并以 JSON 只读预览；未登记 Redis Key 只按原始类型读取，二进制内容使用 Base64，禁止通用 Java 对象反序列化；
- 文件存储配置不进入缓存目录和缓存 Value 查询；
- 单次 Value 最多读取 100 项或 64 KiB，单次最多删除 100 个 Key；
- 操作日志不得记录 Redis Value 或被删除 Key 的完整请求内容。

## 图表边界

页面只展示 Redis 当前快照与 JetCache 当前节点、本统计周期快照。Apache ECharts 只表达 Redis 内存和本周期命中/未命中构成，当前不持久化历史趋势；统计会随对应实例重启或其定时统计周期重置。页面默认每 10 秒刷新并允许关闭自动刷新。
