# SQL 控制台

## 模块边界

- SQL 控制台属于运维中心下的高风险 PostgreSQL 运维能力，不是面向普通业务用户的查询或报表工具；
- 支持单条查询、DML 和 DDL；多语句仅允许最多 100 条纯 `INSERT`；
- 批量 `INSERT` 在同一事务中执行，任意语句失败时全部回滚；
- 不支持多结果集、显式事务控制语句、存储过程调用、数据导出、查询收藏和 Schema 自动补全；
- 执行历史属于 SQL 控制台专用审计，不并入通用操作日志。

## 安全边界

- Controller 必须校验对应功能授权，公开 Service 必须再次确认当前账号为 `administrator`；
- DML 和 DDL 由前端显示二次确认，但前端确认不能替代后端鉴权和审计；
- SQL 正文和执行结果不得写入通用操作日志；
- SQL 文本最长 100000 个字符，执行超时为 30 秒；
- 查询行数由系统内置参数 `SQL_CONSOLE_MAX_ROWS` 控制，默认 1000，合法范围为 1～5000；
- 查询多读取一行判断是否截断，超出限制的数据不返回前端；
- 二进制值使用 Base64 返回，不向前端暴露 JDBC 对象或服务端异常堆栈。

## 执行与审计

- SQL 执行和审计日志写入位于同一个 Spring 事务边界；
- SQL 失败时先回滚到执行前保存点，再写入失败审计；
- 审计写入失败不得静默忽略；
- 审计记录 SQL、结果类型、耗时、行数、错误信息、执行人、IP 和执行时间；
- 查询结果通过有序列定义和二维行数组返回，重复列名不会覆盖数据。
- SQL 执行日志按[日志数据生命周期](../../../architecture/log-lifecycle.md)转入历史和淘汰；管理员可以通过本控制台按明确时间范围查询历史父表。

SQL 执行和执行历史使用分离的功能授权；这些授权只应授予 `administrator` 角色，公开 Service 仍执行管理员身份复核。

## 前端交互

- SQL 编辑器使用 CodeMirror 6 的 PostgreSQL 方言支持；
- 页面使用 Ant Design 纵向 `Splitter` 分隔 SQL 编辑区和结果区；
- 有选区时 `Ctrl + E` 执行选区，无选区时执行全部内容；
- 查询结果显示列类型、行数、耗时和截断状态；批量 `INSERT` 显示每条语句影响行数；
- 编辑器实例随工作台页签销毁，首版不将 SQL 草稿写入浏览器持久化存储。
