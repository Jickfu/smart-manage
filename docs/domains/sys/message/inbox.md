# 站内消息

## 模块定位

站内消息位于系统领域的“消息服务”应用，负责管理员全站消息、当前用户消息中心和未来业务通知的稳定接入边界。站内消息不发送邮件，不依赖 SMTP 账号、邮件任务或邮件发送状态。

管理员发布是具有独立状态的业务聚合，使用 `LIST + EDIT` 页面。个人消息中心是所有登录用户均可使用的 Header 全局能力，不要求用户拥有“消息服务”应用访问权限。

## 发布与收件边界

- 全站消息仅允许真实 `administrator` 发布和失败重试；这两个命令的 Controller 权限码和公开 Service `@AdministratorOnly` 缺一不可。列表、详情和草稿保存仍按功能权限授权。
- 消息状态为 `DRAFT`、`PENDING`、`PUBLISHING`、`PUBLISHED` 和 `FAILED`。只有草稿可以保存；发布使用独立命令，不进入保存 Form。
- 发布任务在后台领取后，以同一数据库事务查询当前已启用用户并生成收件记录。事务提交时间才是正式发布时间，因此事务快照之后新增的用户不会补收历史消息。
- 消息正文只在主体表保存一份，用户已读状态保存在独立收件表。发布完成后正文不可修改。
- 发布失败不产生部分可见的收件结果；失败重试复用原消息和幂等约束，不创建重复收件记录。
- 首期正文只支持纯文本，不执行 HTML，不接受任意 URL 或前端组件路径。

## 数据与查询

`t_sys_inbox_message` 保存消息主体、场景幂等键、发布状态和收件人数。`t_sys_inbox_recipient` 保存 `message_id + user_id + received_time`、`read_status` 和 `read_time`。

收件表按 `received_time` 建 PostgreSQL 月度范围分区。个人列表默认只查询最近 365 天，使用 `(received_time, message_id)` 游标，不使用深分页 OFFSET。每个分区为当前用户时间线和未读记录建立索引；Header 未读角标最多计数 100 条并展示 `99+`，避免无界精确计数。

消息失效时间最多为一年，与个人消息在线查询窗口保持一致，避免创建仍有效但已退出查询窗口的消息。

`read_status` 与 `read_time` 同时更新：未读必须没有阅读时间，已读必须具有阅读时间。个人接口不接受目标用户 ID，始终从 `CurrentUserContext` 获取当前用户，并以 `user_id + received_time + message_id` 校验对象归属。

`received_time` 同时承担分区键和游标键。接口使用数据库生成的六位微秒字符串原样往返，不能经过系统全局的秒级日期序列化，否则会因精度截断导致详情、已读命令定位失败或游标漏数。

当前只建立在线分区和未来分区余量。物理清理策略在明确业务与合规保留期后通过独立、固定表白名单的生命周期任务实现；不得由普通请求动态执行 DDL。

## 业务通知预留

模块提供 `InboxNotificationPublisher` 最小 Contract，输入场景键、幂等键、收件用户、标题、纯文本正文和可选业务资源引用。调用方只能提交用户 ID，消息模块负责校验用户有效状态和创建收件记录。

未来工作流必须在自身事务内先写本领域 Outbox，事务提交后再调用站内消息 Contract。任务通知使用稳定幂等键，例如 `workflow.task.assigned:{taskId}:{assignmentVersion}`，不得让工作流直接操作站内消息表。

业务资源字段只保存稳定 `resourceType`、`resourceId` 和 `actionCode`，首期不实现通用路由或动态动作平台。出现真实工作流页面后，再由资源提供方按当前用例实现最小、受权限复核的跳转解析。

## 前端交互

- Header 显示未读角标。全局系统参数 `INBOX_POLL_INTERVAL_SECONDS` 默认 `60` 秒，`0` 关闭定时轮询；启用值必须为 `10～2147483` 秒的整数，上限避免浏览器毫秒定时器溢出。系统参数保存时校验，消费非法配置时返回配置错误，不降级成高频轮询。
- 轮询只刷新未读摘要，页面不可见时暂停；每次摘要响应同时返回当前间隔。参数调整在下一次摘要刷新后生效，关闭轮询后可通过打开预览或重新聚焦窗口读取新配置。
- 消息按钮切换 Ant Design 右侧 Drawer：没有遮罩和焦点锁定，从 Header 下边缘延伸至视口底部，背景页面仍可交互。顶部为任务、消息、更多；消息预览在服务端过滤已读后按稳定倒序读取最新 10 条未读消息，不显示条数说明，标题单行、正文两行省略。预览不标记已读。
- 点击预览消息或更多进入 Header 单实例“消息中心”页签；该页签不创建业务应用工作台、不依赖消息发布应用权限，具有与应用一致的关闭、切换保留和服务端固定恢复行为。保留键为 `builtin:inbox`，业务应用不能使用该编码。
- 中心左侧使用与应用侧栏一致的深色分类栏，顶部切换消息和任务，下方使用平铺分类按钮，不使用树形菜单；消息类型直接映射既有 `audience_type`：系统公告为 `ALL_ENABLED_USERS`，业务通知为 `USERS`。消息类别右侧显示各自近一年的未读数，不受右侧本月筛选影响，独立封顶100并展示99+，与Header摘要一同刷新；任务预留待处理、已处理、我发起的分类，统一显示暂未开放，不请求或虚构任务数据。
- 右侧具有与应用工作台共享的内容页签栏；页签栏只展示首页图标和已打开的消息详情，不为左侧分类建立页签。左侧分类切换首页中的消息列表，标题是详情入口，摘要仅展示。打开详情保留列表过滤、已加载记录和滚动位置；切换分类重置该列表查询及选择。详情按完整收件键单实例，最多打开20个，支持切换、关闭、关闭其他及关闭全部，首页图标始终返回列表。复用既有列表样式，按标题与筛选、命令栏、表格元信息与紧凑表格分层排列，保持列表密度、表格主题和错误反馈一致；这属于个人消息中心的专用交互，不增加管理员 LIST/EDIT 页面或通用消息路由平台。列表首次默认“未读 + 本月”，默认条件统一显示在过滤摘要及对应表头中，不再提供顶部独立选择器，查询在服务端过滤后使用游标加载更多，不返回伪造总数或采用 OFFSET。状态、标题、内容、发送人、接收时间统一使用表头过滤和服务端白名单协议，内容针对完整正文过滤；状态复用普通枚举过滤的竖排复选框和全选、重置、确定操作，全选或清除状态条件可查看全部状态，顶部状态摘要不显示“是”；清除接收时间条件后使用近一年查询边界，所有过滤都发生在游标截取前。
- 详情从预览携带完整收件键直接打开并追加或激活内容页签，不重建消息中心，不受列表初始筛选限制。成功读取详情后才自动标记已读，支持手动已读/未读；详情复用 `EditPageShell`，上方独立按钮栏，下方为四周10px间隔的白色消息内容区；正文继续只按纯文本渲染。全部已读明确提示作用于近一年全部消息，不受当前筛选限制。
- 消息和详情数据、已读命令及缓存失效由 TanStack Query 管理；Zustand 仅保存 Header 页签和本次导航目标。隐藏中心页签不主动查询列表或详情，关闭中心释放其界面状态。

## 界面扩展基线

本轮为 `sys/message/inbox` 的个人查询能力扩展，不新增发布聚合。主参考为现有收件游标接口、Header 应用页签和系统参数 LIST/EDIT；列表保留游标语义，因此不接入要求精确总数的通用分页壳。权限和当前用户对象归属保持不变，固定配置复用个人应用固定表的用户锁和顺序；迁移约束保证业务应用 ID 与白名单内置键恰好二选一。管理员发布页面继续使用 `sys/message/inbox-broadcast` Feature。
- 管理员页面位于“消息服务 → 站内消息 → 消息发布”，草稿可编辑，待发布、发布中和已发布记录只读。

## 验收风险

- 非 `administrator` 即使拥有权限码也不能发布或重试全站消息。
- 发布只包含事务快照中的启用用户，新注册用户不补收，停用用户不收取。
- 并发领取不会重复发布，同一用户对同一消息最多一条收件记录。
- 发布事务失败时主体状态与收件记录保持一致，不出现部分可见结果。
- 用户不能查看或修改其他用户的收件状态；重复已读命令保持幂等。
- 列表使用游标和时间下限，未读角标使用部分索引与封顶计数。
