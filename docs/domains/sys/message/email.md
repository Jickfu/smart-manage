# 邮件服务

## 模块定位

邮件服务位于系统领域的独立“消息服务”应用。首期只支持 SMTP，负责发信账号、管理员正式发信、持久化投递任务和发送记录；登录、密码重置和工作流等业务尚未接入。

内置场景包括管理员手工发信 `admin.manual` 和监控告警 `monitor.alert`。监控领域通过最小稳定 `EmailNotificationSender` Contract 提交用户引用、主题、正文和幂等键，不直接依赖 SMTP 配置或邮件内部 Service。

## 发信账号

- 支持多个 SMTP 账号和唯一全局默认账号。
- 新增账号固定以停用状态保存；启用、停用只通过列表页专用命令修改，账号编辑保存不携带启用状态。
- 管理员显式选择账号时，该账号必须启用且允许手工选择；未选择时使用全局默认账号。
- 指定账号停用或配置失效时直接失败，不自动切换发件身份。
- 密码或授权码通过 SM4/GCM 加密入库，接口只返回是否已配置。
- 已产生发送记录的账号只能停用，不能删除。
- 账号配置、测试和正式发信同时校验权限码与真实 `administrator` 身份。

## 投递与状态

正式发信先写入 `t_sys_email_task`，提交后由启用的内置 Quartz 任务 `SYSTEM_EMAIL_DISPATCH` 每 15 秒领取。领取使用 PostgreSQL `FOR UPDATE SKIP LOCKED`，支持多实例并避免正常重复领取。

状态为 `PENDING`、`SENDING`、`SUCCESS`、`RETRY_WAIT`、`FAILED`、`UNKNOWN` 和 `CANCELLED`。`SUCCESS` 仅表示 SMTP 服务器接受邮件，不表示最终送达。临时 SMTP 错误最多尝试三次并指数退避；账号停用等配置错误不重试。每次尝试追加写入 `t_sys_email_attempt`。

重新发送会创建关联原任务的新任务，原始内容和结果不可修改。只有等待发送的任务可以取消。

## 安全边界

- 管理员发信的收件人、抄送和密送统一选择系统用户，前端只提交用户 ID；后端在入队前校验用户有效状态并解析邮箱地址，普通用户列表不因此暴露邮箱字段。
- 单封邮件最多 50 个收件地址，正文和主题有固定长度上限。
- HTML 拒绝脚本、iframe、表单、事件处理器和 `javascript:` 链接；详情页只展示源码，不执行 HTML。
- 操作日志不记录账号保存、连接测试和邮件正文等请求载荷。
- SMTP 凭据、认证信息和完整协议交互不得进入接口、缓存、日志或异常。
- 首期不支持附件、定时发送、大规模群发、打开追踪或供应商 HTTP API。
