# 安全架构

## 认证

登录页是独立 HTML 页面。页面获取图文验证码，使用 SM2 C1C3C2 模式加密密码和验证码，再调用登录接口。浏览器端 `sm2.js` 输出的 C1 非压缩点不含 `04` 前缀，后端必须通过浏览器密文专用入口统一补齐后再解密，不能依赖密码库按首字节猜测密文格式。畸形、截断或无法解密的密文统一按参数异常处理并记录登录失败审计，不得穿透为服务端异常，也不得记录原始密文。token 当前保存在 localStorage，并通过 `smtoken` 请求头发送。

当前明确保留 localStorage 认证方案，不迁移 Cookie。SM2 和可选请求加密不能替代 TLS。

401 响应必须清理 localStorage 和 Zustand 中的认证状态，再跳转登录页。服务端支持主动注销和 token 失效。

## 权限

前端权限只控制能力展示，后端是最终鉴权边界。普通接口使用权限码；`administrator` 拥有 `*` 通配权限。

SQL、脚本、Arthas、定时任务命令等高风险能力必须同时满足：

1. Controller 权限码校验；
2. 公开 Service 入口确认当前账号确实为 `administrator`。

高风险身份校验不能只依赖可配置权限码。

附件等通用能力不能只校验接口权限码。正式附件必须通过 `bizType + bizId` 找到已注册的业务资源授权策略，并继承所属单据或系统资源的对象级权限；临时附件按上传者和上传会话校验。未知资源类型、缺少归属、资源不存在或授权策略异常时默认拒绝，不以创建人独占或逐附件用户授权表替代业务权限。

## 浏览器与生产边界

- 登录页和 React 应用使用 CSP 限制脚本、连接、图片、字体和对象来源。
- 登录脚本内容和 CSP SHA-256 摘要必须保持一致，并由自动化测试防止漂移。
- 生产环境关闭 Swagger、Scalar、Druid 监控页和 Arthas。
- 生产环境 Actuator 只暴露不含详情的健康检查。
- 日志和异常输出禁止记录 token、密码、验证码、私钥、密钥和存储凭据。

## 管理员凭据

开发和演示环境可以使用公开的默认管理员凭据。生产环境必须显式提供非演示密码；配置缺失或仍使用 `admin` 时不得静默启动。

系统只在数据库仍保留演示密码时执行一次替换，不覆盖管理员后续主动修改的密码。

## 服务端配置加密

- 文件存储密码等服务端敏感配置使用 SM4 加密后入库；
- SM4 密钥只允许通过部署环境变量或外部密钥管理设施注入，禁止存入系统参数、业务表或管理端页面；
- 生产环境必须显式提供有效密钥，缺失或格式错误时应用拒绝启动；
- 密钥轮换必须和既有密文重新加密作为一个受控运维流程，禁止直接替换密钥导致历史数据无法解密；
- 日志、异常信息、接口响应和缓存不得输出密钥或明文凭据。

## 尚未生效的方案

账号/IP 失败窗口、动态锁定和验证码频率限制仍处于[登录保护提案](../proposals/login-protection.md)阶段，当前不能视为已实现能力。
