# 安全架构

本文档是认证会话、功能鉴权执行、高风险身份复核、浏览器请求安全和服务端凭据保护的主边界。功能目录归[功能与权限架构](./feature-and-permission.md)，行级与对象范围归[数据权限设计](./data-permission.md)，隐私字段出站归[数据脱敏架构](./data-masking.md)。

## 认证

登录页是独立 HTML 页面。用户提交用户名和密码后弹出滑块拼图；服务端原子消费挑战并签发绑定用户名的短时一次性票据，登录接口原子消费票据后再验证密码。密码使用 SM2 C1C3C2 模式加密，滑块票据是短时高熵随机凭证，不额外使用 SM2 加密。浏览器端 `sm2.js` 输出的 C1 非压缩点不含 `04` 前缀，后端通过系统安全层的 `BrowserPasswordCipher` 明确校验密文格式、补齐前缀并直接委托 Bouncy Castle 完成 SM2/SM3 运算，禁止依赖第三方工具类的启发式格式猜测或自行实现密码学原语。应用启动时必须校验 SM2 公私钥格式及匹配关系，缺失或非法时拒绝启动，禁止返回原文或降级绕过。畸形、截断、被篡改或无法解密的密码密文统一按参数异常处理并记录登录失败审计，不得穿透为服务端异常，也不得记录原始密文。

滑块挑战、验证票据、账号/IP失败窗口和验证码频率限制统一遵守[登录保护架构](./login-protection.md)。这些状态使用共享 Redis；Redis 不可用时拒绝认证，不回退到单实例状态或绕过保护。

浏览器认证使用名为 `smtoken` 的持久化 HttpOnly Cookie，前端脚本不得读取、保存或在请求头中传递认证 token；服务端不再从请求头或请求体读取浏览器认证凭证。Cookie 固定使用 `Path=/`、`SameSite=Lax` 且不设置 `Domain`，`Secure` 由部署配置显式开启，未开启时不能抵御 HTTP 链路上的凭证窃取。SM2 和可选请求加密不能替代 TLS。

登录会话创建时必须生成与当前 Token Session 绑定的独立 CSRF Token。Token 使用 16 字节安全随机数据编码为 32 个十六进制字符，通过会话初始化接口返回并只保存在前端内存；所有已认证的 `POST`、`PUT`、`PATCH`、`DELETE` 请求必须通过 `sm-csrf-token` 请求头提交。浏览器接口的所有非安全方法（包括登录前公开接口）还必须校验 `Origin` 是否属于 `smart-manage.infrastructure.cors.allowed-origins`；`GET`、`HEAD`、`OPTIONS` 禁止承担状态修改。

`/openapi/**` 是唯一的服务到服务入站边界，不读取 Cookie、Sa-Token 或浏览器 CSRF Token，也不要求 `Origin`。该路径必须先经过 OpenAPI 独立安全过滤器，完成已发布路由识别、Key ID 与应用状态校验、可信代理边界下的客户端 IP 策略、时间窗、密文摘要、HMAC 签名、Redis nonce 重放防护、API 授权和 GCM 报文解密，之后才能建立请求级代理用户与固定组织上下文。未知路由和认证失败默认拒绝，普通 `@SaIgnore` 接口不得借用该例外。

正式登录必须从用户唯一的有效主职任职建立当前组织上下文；未分配主职、主职组织已停用或已封存时拒绝登录。当前组织不得回退到固定组织 ID，`administrator` 同样必须具有明确主职，但其高风险身份与全局功能权限仍按独立规则校验。

主应用通过 `GET /sys/base/session` 初始化当前用户、组织上下文和 CSRF Token，应用、菜单与权限仍按页面需要独立查询。401 响应由服务端清除认证 Cookie，前端只清理 Zustand 会话快照并跳转登录页；CSRF 校验失败使用独立业务码 `100419`，不得清除正常登录状态。主动注销必须同时注销服务端会话并删除 Cookie。

用户删除、禁用或密码重置等安全事件必须在数据库事务成功提交后终止该用户全部现有会话并刷新授权缓存。会话初始化时若登录 ID 对应用户不存在或已禁用，必须终止登录态并统一返回未登录，不能返回空用户、暴露具体账号状态或穿透为服务端异常。

用户管理、当前用户资料、凭据校验、角色授权和登录会话使用独立 Service 边界。登录流程只依赖专用认证与资料接口；Sa-Token 会话创建由登录包内组件封装，不通过公开用户 CRUD Service 暴露，也不得成为脚本控制台可调用的公开 Service。

管理员排查生产问题时可以为非 `administrator` 用户生成一次性代登录凭证。凭证使用固定版本前缀和高熵随机值，Redis 仅以 SHA-256 摘要为键保存五分钟，并在登录时通过原子读取删除保证只能消费一次。生成前必须由真实 `administrator` 使用本人密码完成五分钟有效的二级认证并填写原因；目标用户名不匹配同样消费凭证。代登录复用普通登录页、滑块验证和 SM2 加密，成功后创建独立的三十分钟固定期限会话，权限与目标用户正常密码登录完全一致，不增加页面提示或额外业务限制。禁止为 `administrator` 生成凭证，日志不得记录凭证明文或摘要。

## 权限

### 邮箱找回与验证

邮箱找回密码使用完整邮箱识别账号，只允许已验证邮箱且禁止 `administrator` 使用。发送接口在账号不存在、未验证、已禁用或不允许找回时统一返回相同结果，避免账号枚举；发送前复用登录滑块一次性票据。邮箱验证码为 6 位数字，Redis 仅保存摘要、用户绑定、失败次数和短时有效状态，新验证码会替换旧验证码。验证码邮件属于敏感系统邮件，正文加密持久化、管理接口不得返回、不得重新发送，并在投递进入最终状态后清除正文密文。重置成功后必须终止该用户全部现有会话。

用户邮箱只有完成发送到新地址的验证码校验后才标记为已验证。历史邮箱和管理员直接维护的邮箱默认未验证；个人中心通过邮箱修改密码时只能向当前已验证邮箱发送验证码。邮箱按去除首尾空格并忽略大小写唯一，手机号按去除首尾空格唯一，数据库唯一索引是并发写入的最终保障。

前端权限只控制能力展示，后端是最终鉴权边界。普通接口使用权限码；`administrator` 拥有 `*` 通配权限。

Feature 只组织页面、菜单和权限，不直接授予能力。角色仍授予具体权限；功能目录可见性不能替代接口鉴权、数据权限或对象级授权。

SQL、脚本、线程诊断、定时任务命令等高风险能力必须同时满足：

1. Controller 权限码校验；
2. 公开 Service 入口通过 `@AdministratorOnly` 确认当前账号确实为 `administrator`。

完全属于高风险能力的 Service 使用类级 `@AdministratorOnly`，使后续新增公开入口默认受到保护；同时包含普通内部能力的 Service 使用方法级标记。身份校验由优先于业务日志的统一切面执行，拒绝请求不得进入目标方法或触发业务副作用。方法级标记依赖 Spring AOP 代理，禁止同类调用此类入口；需要复用时提取私有实现，并由每个公开入口分别声明保护。该约束由 ArchUnit 检查。高风险身份校验不能只依赖可配置权限码，也不得在各业务方法中散落直接安全上下文调用。

附件等通用能力不能只校验接口权限码。正式附件必须通过 `bizType + bizId` 找到已注册的业务资源授权策略，并继承所属单据或系统资源的对象级权限；临时附件按上传者和上传会话校验。未知资源类型、缺少归属、资源不存在或授权策略异常时默认拒绝，不以创建人独占或逐附件用户授权表替代业务权限。

## 浏览器与生产边界

- 登录页和 React 应用使用 CSP 限制脚本、连接、图片、字体和对象来源。
- 登录脚本内容和 CSP SHA-256 摘要必须保持一致，并由自动化测试防止漂移。
- 生产环境关闭 Swagger、Scalar 和 Druid 监控页。线程诊断只使用 JDK 原生管理接口，不开放 Agent、Telnet、任意命令或 OGNL；跨实例调用必须从 Redis 注册表解析内部地址，并在目标节点重新执行登录、权限和真实 `administrator` 身份复核。
- 所有环境均不通过 Web 暴露 Actuator 端点；内建监控只在进程内调用 Actuator Bean 获取健康状态。
- 日志和异常输出禁止记录 token、密码、验证码、私钥、密钥和存储凭据。

## 管理员凭据

开发和演示环境可以使用公开的默认管理员凭据。生产环境必须显式提供非演示密码；配置缺失或仍使用 `admin` 时不得静默启动。

系统只在数据库仍保留演示密码时执行一次替换，不覆盖管理员后续主动修改的密码。

## 服务端配置加密

- 文件存储密码等服务端敏感配置使用带版本标识的 SM4/GCM 认证加密后入库；密文必须同时具备保密性和完整性，禁止使用无 MAC 的 CBC 密文；
- SM4 密钥只允许通过部署环境变量或外部密钥管理设施注入，禁止存入系统参数、业务表或管理端页面；
- 生产环境必须显式提供有效密钥，缺失或格式错误时应用拒绝启动；
- 密钥轮换必须和既有密文重新加密作为一个受控运维流程，禁止直接替换密钥导致历史数据无法解密；
- 日志、异常信息、接口响应和缓存不得输出密钥或明文凭据。

业务隐私字段与凭据清除的当前规则见[数据脱敏架构](./data-masking.md)。
