# 登录保护架构

## 目标与边界

登录保护用于降低 OCR、密码猜测、撞库、验证码资源滥用和单账号攻击风险。登录页使用弹出式滑块拼图；图片生成和轨迹匹配复用 `tianai-captcha` 核心库，接口、Redis 状态、一次性票据、限流、审计和登录绑定由项目维护。

首版只启用滑块拼图，不启用文字点选、客户端风险评分或免验证路径。普通密码登录、首次改密前的认证和管理员代登录均使用同一保护链路。

## 认证协议

```text
提交登录表单
  → POST /sys/base/captcha/challenge
  → 弹出滑块并采集有限轨迹
  → POST /sys/base/captcha/verify
  → 服务端原子消费挑战
  → 返回短时一次性 captchaTicket
  → POST /sys/base/login
  → 服务端原子消费 captchaTicket
  → SM2 解密并校验密码或代登录凭证
  → 建立登录会话
```

- 创建挑战和验证挑战都是 `POST`，必须通过登录前公开接口的 Origin 校验。
- 挑战答案只保存在共享 Redis；任何一次验证尝试都会消费挑战，禁止反复试探坐标。
- 验证成功签发 32 字节安全随机数据编码的票据。票据绑定规范化用户名摘要，只能消费一次。
- 登录接口不接受坐标、轨迹或客户端 `verified` 标志，只接受短时票据。
- 密码继续使用 SM2 C1C3C2 模式加密。验证码票据本身是短时高熵随机凭证，不额外使用 SM2 加密。
- Redis 不可用时禁止创建挑战、验证挑战和登录，不回退到进程内状态，也不绕过验证。

## 滑块数据边界

- 服务端决定验证码类型、图片尺寸、模板和允许误差，客户端不能请求任意类型或尺寸。
- 前端只提交展示尺寸、最终位置、起止时间和最多 512 个轨迹采样点。
- 轨迹属于不可信输入，只参与验证码库匹配，不能单独代表验证成功。
- 图片和脚本资源随项目发布，不依赖运行时 CDN。
- 登录日志、异常和缓存管理界面不得输出挑战答案、完整轨迹、票据或第三方库内部验证数据。

## 多维失败窗口

登录失败同时维护账号、客户端 IP、账号与 IP 组合三个维度：

- 账号与 IP 组合优先限制单一来源对单一账号的连续尝试；
- IP 维度限制同一来源对多个账号的攻击，内网共享出口应配置更宽松阈值；
- 账号维度只使用短时保护，禁止配置成长时间全局账号锁定，降低恶意锁定他人账号的风险；
- 登录成功后清除账号和账号 IP 组合状态，IP 状态按窗口自然过期；
- 已建立的登录会话不受后续登录失败计数影响。

客户端 IP 必须通过现有 `ClientIpResolver` 获取，只信任已配置代理网段传递的转发头。

## 验证码资源限制

- 同一 IP 创建挑战有最小时间间隔；
- 同一 IP 有每分钟创建上限；
- 挑战和票据均有短时 TTL；
- 验证失败立即消费挑战；
- Nginx 可以增加基础限流，但应用层 Redis 限流仍是跨实例一致性的权威边界。

## 运行参数

运行阈值统一使用系统内置参数，不再维护一套 YAML 阈值。参数由 Flyway 初始化，系统内置参数不可删除，管理员修改 `value` 后通过远程缓存失效在多实例生效。允许范围、影响和运维建议写在参数描述中，参数必须能解析为正整数，否则认证按配置异常失败。

| 参数 | 含义 |
| --- | --- |
| `LOGIN_CAPTCHA_CHALLENGE_EXPIRE_SECONDS` | 滑块挑战有效期 |
| `LOGIN_CAPTCHA_TICKET_EXPIRE_SECONDS` | 登录票据有效期 |
| `LOGIN_CAPTCHA_MIN_INTERVAL_MILLIS` | 同一 IP 创建挑战最小间隔 |
| `LOGIN_CAPTCHA_IP_MAX_PER_MINUTE` | 同一 IP 每分钟挑战上限 |
| `LOGIN_FAILURE_WINDOW_MINUTES` | 登录失败统计窗口 |
| `LOGIN_ACCOUNT_MAX_FAILURES` | 账号短时保护阈值 |
| `LOGIN_ACCOUNT_BLOCK_SECONDS` | 账号短时保护时间 |
| `LOGIN_IP_MAX_FAILURES` | IP 保护阈值 |
| `LOGIN_IP_BLOCK_MINUTES` | IP 保护时间 |
| `LOGIN_ACCOUNT_IP_MAX_FAILURES` | 账号 IP 组合保护阈值 |
| `LOGIN_ACCOUNT_IP_BLOCK_MINUTES` | 账号 IP 组合保护时间 |

## 错误和审计

- 用户不存在与密码错误统一提示“用户名或密码错误”；
- 密码正确后的账号停用、主职缺失和组织不可用可以返回可操作提示；
- 验证码过期、校验失败和请求受限使用独立错误类别；
- 详细认证失败原因写入登录审计，但不得记录密码、密文、挑战答案、轨迹或票据；
- Redis 故障属于认证基础设施故障，不计入用户失败次数。

## 验证要求

- 覆盖挑战一次消费、票据账号绑定、票据一次消费和过期；
- 覆盖账号、IP、账号 IP 组合窗口及成功清理；
- 覆盖验证码创建频率限制和 Redis 故障失败关闭；
- 覆盖普通登录、首次改密和代登录；
- CSP 测试必须约束登录页内联脚本哈希；
- 浏览器验证桌面弹层交互，并对手机触控保留基本可用性检查；
- 多实例环境验证挑战与票据可以跨实例创建、验证和消费。

## 邮箱找回密码

忘记密码在登录页右侧原位完成，不建立登录会话。用户提交完整邮箱后先完成既有滑块验证，服务端消费绑定该邮箱的滑块票据，再按安全架构统一响应并异步发送 6 位验证码。验证码验证与密码写入必须形成一次性命令：错误尝试累计，达到上限或成功后立即失效；新密码通过既有 SM2 浏览器密码通道传输并使用 Argon2 存储。手机号找回仅保留不可用入口，不签发短信验证码。
