# 数据权限设计

本文档只定义 DataScope 解析、组织范围合并和对象级授权边界，不定义功能权限目录，也不表示所有模块已自动具备行级隔离。功能权限见[功能与权限架构](./feature-and-permission.md)。

## 当前状态

角色数据范围公共能力已经生效，采购申请是首个完整接入样板，覆盖列表、详情、保存、删除、提交、附件授权和首页统计。其他业务资源只有在注册表显式声明支持 DataScope 并完成领域字段解释后才能接入，禁止把采购语义自动套到系统参数、菜单等无组织归属资源。

当前先统一数据归属字段：具有保存、提交、审核等生命周期的业务单据继承 `BaseBillEntity`，使用 `org_id` 表达单据所属组织。`applicant_id`、采购员、经办人、负责人等字段不是所有单据共有的语义，只能由具体聚合按业务需要声明。

## 权限分层

功能权限回答“能否执行某项能力”，继续使用现有权限码。数据权限回答“可以访问哪些业务对象”，不得用新增功能权限码模拟数据范围。

支持以下标准范围：

```text
ALL                 全部数据
ORG_AND_CHILDREN    当前组织及下级组织
ORG                 当前组织
SELF                本人相关数据
CUSTOM_ORGS         指定组织集合
```

同一用户在当前组织下的有效角色包含手工分配与可选默认角色，默认角色的数据范围同样按当前组织解释（见[角色管理](../platform/base/role.md#默认角色)）。拥有多个有效角色时，授权范围按并集合并；`administrator` 固定为 `ALL`。切换当前组织后必须重新解析数据范围，不能复用其他组织上下文中的结果。

这里的 `administrator` 指由统一安全上下文确认的管理员账号身份，与角色编码无关。所有新建角色（包括编码为 `admin` 的角色）默认 `SELF`，数据范围统一通过专用分配命令维护；普通角色资料保存不得改写已有范围，也不得因角色编码赋予 `ALL` 或禁止配置。既有角色的授权值不因取消编码特判自动重置。角色配置交互见[角色管理](../platform/base/role.md)。

## 后端边界

跨领域通过 `sm.system.datascope.DataScopeResolver.resolve(resourceType, action)` 获取合并后的 `all`、`selfIncluded`、组织 ID 集合和当前用户 ID；`DataScopeService` 是系统管理领域内的实现，不作为跨领域依赖入口。

## 配置继承与合并

DataScope 采用“角色默认 + 资源默认 + 操作覆盖”的三级继承：

1. Action 未配置时继承 Resource；Resource 未配置时继承 Role。
2. 用户在当前组织拥有多个角色时，先分别求有效规则，再对 Allow 范围取并集。
3. `administrator` 固定为 `ALL`；不提供 Deny、优先级或策略冲突引擎。
4. `CUSTOM_ORGS` 使用关系表保存，不能写入 JSON。
5. Action 是业务资源的数据访问语义，不要求等同功能权限或按钮动作。
6. 只有注册表显式声明支持 DataScope 的资源才参与解析。

业务查询必须显式把该上下文传给 Mapper，由可读 SQL 或类型安全 Wrapper 生成条件。初始版本禁止通过 ThreadLocal SQL 拦截器自动向任意查询拼接 `org_id`，因为审批人、申请人、协作人和所属组织并不总是同一语义，自动改写也难以审计复杂联表和统计查询。

详情、修改、删除、提交和附件访问不能只依赖列表过滤。对象级策略至少组合校验：

```text
功能权限
+ 数据范围
+ org_id 等对象归属
+ 具体业务角色字段
+ 单据状态
```

对象授权查询只加载判断所需的最小字段，不加载完整聚合。

后续业务资源仍需逐一完成领域接入和风险测试；公共解析服务存在不代表所有模块自动具有行级隔离。

## 接入与拒绝路径

`DataScope` 的 `selfIncluded` 只表示合并后的规则包含 SELF，不自动指向创建人、申请人或负责人；由资源所属领域定义哪些字段表达“本人相关”。`orgIds` 为空不等于 ALL，也不能因此省略范围条件。`all`、SELF 与组织集合的组合按本章 Allow 并集解释，不将用户提交的组织 ID 作为可信授权上下文。

查询、详情及命令必须各自覆盖范围外对象的拒绝路径。写入还需在实际事务内核实与本次命令相关的归属、状态和版本，避免列表通过后对象已发生变化；附件与统计沿用同一资源语义，不能只保护列表主查询。资源不支持组织范围时先明确自己的对象访问规则，不机械增加 `org_id` 或套用采购样板。
