# 部署与多实例架构

多实例必须配置唯一 `instanceId`。内建监控通过每 JVM `registrationToken` 原子拒绝重复活跃 ID，并使用稳定 `hostId` 归并同主机实例，见[内建监控架构](./monitoring.md)。
PostgreSQL 完全不可用的告警必须由数据库平台或外部监控承担；应用内邮件链路不缓存解密后的 SMTP 凭据建立旁路。

## 目标拓扑

Smart Manage 保持模块化单体，不拆分微服务。生产目标部署方式为：

```text
客户端
  → Nginx / 负载均衡器
    → smart-manage-api 实例 A
    → smart-manage-api 实例 B
    → smart-manage-api 实例 N

所有实例共享：
  PostgreSQL
  Redis
  S3/MinIO 对象存储
  Quartz JDBC JobStore
```

应用实例必须尽量无状态，任一实例退出后，请求可由其他实例继续处理。不得依赖进程内状态维持登录、业务一致性、任务唯一执行或文件可见性。

## 反向代理和请求边界

- Nginx 负责 TLS 终止、负载均衡、上传大小限制、基础限流和转发头覆盖。
- 应用只信任配置的代理网段和转发层数；客户端直接提交的 `X-Forwarded-For`、`X-Real-IP` 等头不得成为审计依据。
- 登录态、验证码、一次性票据和 Sa-Token 会话使用共享 Redis，不使用节点粘性作为正确性前提。
- 普通 HTTP 请求不得要求固定路由到原实例。确有节点本地会话的管理能力必须显式声明节点 ID、路由方式和失效语义。
- 生产通过 `SMART_MANAGE_TRUSTED_PROXY_CIDRS` 配置真实代理网段；应用仅在直接来源命中该列表时解析 `X-Forwarded-For`，并从右向左剥离受信代理。Nginx 参考配置见 [`deploy/nginx/smart-manage.conf.example`](../../deploy/nginx/smart-manage.conf.example)。

## 数据库和事务

- 所有实例共享同一 PostgreSQL 数据库，Flyway 迁移是结构和必要初始化数据的唯一来源。
- 应用启动期间由 Flyway 数据库锁保证迁移串行执行；破坏性或长时间迁移仍应在发布流程中受控执行。
- 聚合并发继续使用数据库唯一约束、version 乐观锁、状态条件更新和必要的行锁，不使用 JVM 锁保证跨节点数据一致性。
- 数据库连接池容量按“单实例上限 × 实例数”核算，不能让扩容耗尽 PostgreSQL 连接。

## 缓存和共享状态

- 登录票据和 Token Session 使用共享 Redis；用户安全代际与角色权限由 PostgreSQL 直接校验，不使用授权缓存，也不依赖缓存删除实现撤权。必须按认证请求量评估数据库查询开销和连接池容量。
- V17 安全代际升级需要先完成迁移，再整体切换到新版本节点；禁止旧安全逻辑与新版本混合承接流量。历史会话和旧格式改密票据失效，用户需要重新登录；废弃授权缓存与旧验证码键按原 TTL 回收，禁止通过兼容读取恢复旧证明。
- LOCAL/Caffeine 缓存只允许保存可丢弃且允许短暂不一致的数据；写操作必须在事务提交后通过 Redis 广播、版本键或删除共享缓存实现跨节点失效。
- 不具备跨节点失效机制的业务缓存应改为 REMOTE，不能依赖请求再次命中原节点。
- 缓存管理界面必须区分当前节点 LOCAL 状态与集群共享 Redis 状态；当前 LOCAL 缓存查询和清理只作用于接收请求的节点，不承诺集群级广播。
- Redis 分布式锁必须有唯一资源键、租约、超时、所有者校验和异常释放策略；锁不能替代数据库约束。

## 文件与对象存储

- 单实例生产部署可以使用具备持久化、备份和恢复能力的 Local 存储；多实例部署必须使用所有应用实例均可访问的共享存储，可选择 S3 兼容对象存储或 FTP，优先使用 S3/MinIO。
- 数据库只保存对象键、存储类型、元数据和业务归属，不保存节点本地绝对路径。对象键由服务端随机生成，详细规则见[附件与对象存储](../domains/sys/base/attachment.md)。
- 对象键由服务端生成并规范化，禁止接受可穿越路径；Bucket、前缀、大小、扩展名、MIME 和访问范围由存储策略控制。
- 上传、promote、删除与数据库事务不能原子提交，必须记录精确对象键并实现幂等补偿或可重试清理。
- 下载必须执行权限码和对象级归属校验。临时对象不得因对象键可猜测而公开访问。
- Local 存储不得用于多实例部署；FTP 可作为共享存储方案，但新增生产部署优先选择 S3/MinIO。

## Quartz 集群

- Quartz 使用共享 PostgreSQL JDBC JobStore，并开启集群模式、实例唯一 ID、故障检测和恢复。
- 同一 Trigger 在集群中只能由一个实例获取并执行；任务实现必须考虑节点故障后的重复执行，具有幂等键或可检测的执行状态。
- `@DisallowConcurrentExecution` 只约束同一 JobDetail；跨不同任务的共享资源互斥使用 Redis 分布式锁或数据库锁。
- `mutexKey` 的锁必须跨实例生效，获取失败记录 `SKIPPED`；租约应覆盖合理执行时间并支持续期或明确的超时失败语义。
- 任务定义以数据库为权威来源。单个实例同步 Quartz 失败不能破坏数据库期望状态；全量同步必须可重复执行。
- 执行实例日志共享落库并携带实例 ID、fire instance ID 和 Trace ID，便于定位实际执行节点和故障恢复。

## 节点本地能力

脚本执行并发许可、进程内线程池和 LOCAL 缓存天然属于单个实例。此类能力必须选择并文档化以下策略之一：

1. 通过节点 ID 定向到指定管理实例；
2. 只在独立管理实例启用；
3. 将状态外置并实现真正的集群能力。

不得把 JVM `Semaphore`、本地 Map 或本地线程会话描述为集群级互斥或共享会话。

运行监控和线程诊断通过 Redis 在线实例注册表选择目标实例，再由后端定向调用目标节点内部管理接口。浏览器不能提供目标 URL，目标节点必须重新校验共享登录态、权限和管理员身份。实例心跳默认每 10 秒写入一次，注册详情 TTL 为 30 秒；优雅停机主动注销，异常退出由 TTL 自动剔除。

## 可观测性和故障处理

- 日志包含 Trace ID 和实例 ID；异步任务显式传播并清理上下文。
- 内建监控在进程内采集应用及其依赖的健康状态。当前不提供外部存活或就绪端点，部署设施不得将 Actuator URL 配置为探针。
- 下线实例先从负载均衡摘除，再等待在途请求和可终止任务结束。
- 对象存储、Redis、Quartz 和数据库故障必须有明确超时、重试、幂等和告警边界，禁止无限重试。

## 当前实施状态

共享 Redis 状态、实例注册与定向诊断、S3/MinIO 与 FTP 实现、Quartz JDBC 集群、PostgreSQL 跨实例互斥、可信代理和优雅停机均已落到代码与配置。外部存活与就绪探针尚未提供。多实例部署不得使用 Local 文件存储；LOCAL 缓存管理当前只查询和清理接收请求的节点，尚未提供集群广播。

发布前仍必须在目标基础设施执行双实例环境验收，覆盖缓存可见性、无粘性登录、Trigger 唯一获取、资源互斥、跨节点附件读写及单实例退出恢复。环境验收是发布门禁，不能由单元测试替代。
