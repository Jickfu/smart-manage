# 部署与多实例架构

多实例必须配置唯一 `instanceId`。内建监控通过每 JVM `registrationToken` 原子拒绝重复活跃 ID，并使用稳定 `hostId` 归并同主机实例，见[内建监控架构](./monitoring.md)。
PostgreSQL 完全不可用的告警必须由数据库平台或外部监控承担；应用内邮件链路不缓存解密后的 SMTP 凭据建立旁路。

## 目标拓扑

Smart Manage 保持模块化单体，不拆分微服务。生产目标部署方式为：

```text
客户端
  → Nginx / 负载均衡器
    → smart-manage-app 实例 A
    → smart-manage-app 实例 B
    → smart-manage-app 实例 N

所有实例共享：
  PostgreSQL
  Redis
  S3/MinIO 对象存储
  Quartz JDBC JobStore
```

应用实例必须尽量无状态，任一实例退出后，请求可由其他实例继续处理。不得依赖进程内状态维持登录、业务一致性、任务唯一执行或文件可见性。

## 支持的部署组合

“节点”在应用集群中表示独立 JVM 实例，不等同于一台主机或一个操作系统。同一发行 JAR 支持以下组合，均需满足本文的共享状态、实例身份和生产安全要求：

| 部署组合 | 配置要求 | 故障隔离范围 |
| --- | --- | --- |
| 同一操作系统内多个 JVM | 每实例独立监听端口、工作目录、日志目录和唯一 `instanceId`；相同 `hostId` | 应用进程故障；操作系统或主机退出会同时影响所有实例 |
| 多主机、每主机一个实例 | 各实例唯一 `instanceId`，各主机独立稳定 `hostId`，内部地址互通 | 应用进程及应用主机故障；仍取决于共享设施和入口可用性 |
| 多主机、每主机多个实例 | 结合以上要求；同主机实例使用相同 `hostId`、不同 `instanceId` 和端口 | 取决于实例分布、入口及共享设施部署 |
| 不同操作系统混合集群 | 各平台具备受支持的 Java 21 运行时，使用同一发行和匹配配置；验证平台相关能力 | 与对应主机拓扑一致，不能由 Java 跨平台性推导所有平台均已验收 |

同机部署可采用 `/opt/smart-manage/node-a` 与 `/opt/smart-manage/node-b` 两个独立目录。例如监听 `8441` / `8442`，实例 ID 为 `node-a` / `node-b`，主机 ID 都为 `host-a`，内部 HTTPS 地址分别对应各自端口。其他实例必须能直接访问这些地址；多主机不能填写仅本机可达的回环地址。每个 JVM 的连接池、内存和线程预算仍需独立计入主机与数据库总容量。同机多实例同样使用共享 S3 或 FTP，不能改用各实例 Local 目录。

各实例必须使用匹配的部署级 SM4 密钥和浏览器 SM2 密钥对；共享 Redis 的数据库编号及 Spring Data Redis / JetCache 两套配置必须一致。HTTPS 证书和路径可按实例分别部署，但 CA 信任链及证书名称校验必须有效。脚本解释器、文件路径、服务托管方式和主机监控属于平台相关能力，应按目标操作系统验证，不能直接照搬 Linux 的 systemd 和路径到 Windows。

2026-10-09 的生产等价验收已覆盖 Ubuntu 24.04 与 CentOS 8 上各一个 Java 21 实例的混合部署，包括无粘性登录、双向 HTTPS 定向诊断、Quartz 获取和互斥、跨节点业务与附件访问、应用进程异常退出、坏 JAR 回退和备份隔离恢复。同日还在 Ubuntu 24.04 上验证了两个 Java 21 实例共存：独立端口、工作目录、日志与 JVM 遥测，共同 `hostId` 正确归并两个唯一 `instanceId`，共享登录、业务及附件可用；排除第二台参与请求并 SIGKILL 原主实例后，同机存活实例继续服务。验收后已恢复原双主机配置并退役临时实例。Windows / Linux 混合集群尚未完成环境验收；支持的拓扑与实际验收范围必须分别说明。共享设施集中在单主机时，不能把应用双实例描述为整机容灾。外部告警验收仍见[路线图](../roadmap.md)。

## 反向代理和请求边界

- Nginx 负责 TLS 终止、负载均衡、上传大小限制、基础限流和转发头覆盖。
- 提供前端 HTML 的入口必须发送 `Content-Security-Policy: frame-ancestors 'none'` 和 `X-Frame-Options: DENY`；前端与 API 分别由不同虚拟主机提供时，在前端虚拟主机设置。HTML `meta` CSP 无法执行 `frame-ancestors`。Nginx 子 `location` 自行声明 `add_header` 时须重复这些响应头，避免丢失继承值；包含前端静态文件与 API 代理的示例见 [`deploy/nginx/smart-manage.conf.example`](../../deploy/nginx/smart-manage.conf.example)，部署时需替换示例中的前端 `root`、域名和证书路径。
- 应用只信任配置的代理网段和转发层数；客户端直接提交的 `X-Forwarded-For`、`X-Real-IP` 等头不得成为审计依据。
- 登录态、验证码、一次性票据和 Sa-Token 会话使用共享 Redis，不使用节点粘性作为正确性前提。
- 普通 HTTP 请求不得要求固定路由到原实例。确有节点本地会话的管理能力必须显式声明节点 ID、路由方式和失效语义。
- 生产通过 `SMART_MANAGE_TRUSTED_PROXY_CIDRS` 配置真实代理网段；应用仅在直接来源命中该列表时解析 `X-Forwarded-For`，并从右向左剥离受信代理。Nginx 参考配置见 [`deploy/nginx/smart-manage.conf.example`](../../deploy/nginx/smart-manage.conf.example)。
- Nginx 示例通过 HTTPS 连接应用并验证内部 CA 与证书名称。同机默认示例端口为 `8441` / `8442`；多主机需替换 upstream 为内网地址，应用监听端口、内部注册地址、证书和 Nginx 校验名称应一致。Java 进程间定向诊断还需单独配置 JVM 的 CA 信任，Nginx 的信任配置不替代 JVM 信任。
- 示例置于 Nginx `http` 上下文中（例如由主配置包含的 `conf.d` 文件）。部署前替换域名、前端目录、证书及内部 CA 路径；使用已有证书完成 `nginx -t` 后再 reload。首次申请证书时先提供 HTTP 验证入口，证书签发后启用 HTTPS server；HTTP-01 验证路径与 ACME 客户端 webroot 必须一致，续期成功后校验并 reload Nginx。
- 访问日志只记录不含查询串的 `$uri`，不记录 Cookie、认证头或请求体；对象存储签名参数不能进入访问日志。示例不启用 `non_idempotent` 重试，已发送的 POST 等写请求不能因故障转发而被透明重放；未发送请求可按 Nginx 规则切换节点。

## 数据库和事务

- 所有实例共享同一 PostgreSQL 数据库，Flyway 迁移是结构和必要初始化数据的唯一来源。
- 应用启动期间由 Flyway 数据库锁保证迁移串行执行；破坏性或长时间迁移仍应在发布流程中受控执行。
- 聚合并发继续使用数据库唯一约束、version 乐观锁、状态条件更新和必要的行锁，不使用 JVM 锁保证跨节点数据一致性。
- 数据库连接池容量按“单实例上限 × 实例数”核算，不能让扩容耗尽 PostgreSQL 连接。

## 缓存和共享状态

- 登录票据和 Token Session 使用共享 Redis；用户安全代际与角色权限由 PostgreSQL 直接校验，不使用授权缓存，也不依赖缓存删除实现撤权。必须按认证请求量评估数据库查询开销和连接池容量。
- 涉及认证协议或凭据声明的升级，必须按发行说明确认会话失效与节点切换要求，不得通过兼容读取恢复已失效证明；迁移和混合版本运行边界遵守[数据库发布规则](../development/database.md#正式发布与升级规则)。
- LOCAL/Caffeine 缓存只允许保存可丢弃且允许短暂不一致的数据；写操作必须在事务提交后通过 Redis 广播、版本键或删除共享缓存实现跨节点失效。
- 不具备跨节点失效机制的业务缓存应改为 REMOTE，不能依赖请求再次命中原节点。
- 缓存管理界面必须区分当前节点 LOCAL 状态与集群共享 Redis 状态；当前 LOCAL 缓存查询和清理只作用于接收请求的节点，不承诺集群级广播。
- Redis 分布式锁必须有唯一资源键、租约、超时、所有者校验和异常释放策略；锁不能替代数据库约束。

## 文件与对象存储

- 单实例生产部署可以使用具备持久化、备份和恢复能力的 Local 存储；多实例部署必须使用所有应用实例均可访问的共享存储，可选择 S3 兼容对象存储或 FTP，优先使用 S3/MinIO。
- 数据库只保存对象键、存储类型、元数据和业务归属，不保存节点本地绝对路径。对象键由服务端随机生成，详细规则见[附件与对象存储](../platform/base/attachment.md)。
- 对象键由服务端生成并规范化，禁止接受可穿越路径；Bucket、前缀、大小、扩展名、MIME 和访问范围由存储策略控制。
- 上传、promote、删除与数据库事务不能原子提交，必须记录精确对象键并实现幂等补偿或可重试清理。
- 下载必须执行权限码和对象级归属校验。临时对象不得因对象键可猜测而公开访问。
- Local 存储不得用于多实例部署；FTP 可作为共享存储方案，但新增生产部署优先选择 S3/MinIO。

## Quartz 集群

- Quartz 使用共享 PostgreSQL JDBC JobStore，并开启集群模式、实例唯一 ID、故障检测和恢复。
- 同一 Trigger 在集群中只能由一个实例获取并执行；任务实现必须考虑节点故障后的重复执行，具有幂等键或可检测的执行状态。
- `@DisallowConcurrentExecution` 只约束同一 JobDetail；跨不同任务的共享资源互斥使用 Redis 分布式锁或数据库锁。
- `mutexKey` 的锁必须跨实例生效，获取失败记录 `SKIPPED`；租约应覆盖合理执行时间并支持续期或明确的超时失败语义。
- 任务定义以数据库为权威来源。单个实例同步 Quartz 失败不能破坏数据库期望状态；全量同步必须可重复执行。
- 执行实例日志共享落库并携带实例 ID、fire instance ID 和 Trace ID，便于定位实际执行节点和故障恢复。

## 节点本地能力

脚本执行并发许可、进程内线程池和 LOCAL 缓存天然属于单个实例。此类能力必须选择并文档化以下策略之一：

1. 通过节点 ID 定向到指定管理实例；
2. 只在独立管理实例启用；
3. 将状态外置并实现真正的集群能力。

不得把 JVM `Semaphore`、本地 Map 或本地线程会话描述为集群级互斥或共享会话。

运行监控和线程诊断通过 Redis 在线实例注册表选择目标实例，再由后端定向调用目标节点内部管理接口。浏览器不能提供目标 URL，目标节点必须重新校验共享登录态、权限和管理员身份。实例心跳默认每 10 秒写入一次，注册详情 TTL 为 30 秒；优雅停机主动注销，异常退出由 TTL 自动剔除。

## 可观测性和故障处理

- 日志包含 Trace ID 和实例 ID；异步任务显式传播并清理上下文。
- 内建监控在进程内采集应用及其依赖的健康状态。当前不提供外部存活或就绪端点，部署设施不得将 Actuator URL 配置为探针。
- 下线实例先从负载均衡摘除，再等待在途请求和可终止任务结束。
- 对象存储、Redis、Quartz 和数据库故障必须有明确超时、重试、幂等和告警边界，禁止无限重试。

## 备份、恢复与发布回退

- 一致性备份必须覆盖 PostgreSQL、附件对象与元数据、匹配的 SM4/SM2 密钥及应用配置；同时保存对应发行制品、前端静态文件和部署材料。密钥与数据的匹配要求见[生产密钥生成与部署](../development/production-keys.md#已有数据库不能按新环境处理)。
- 停写备份必须停止所有应用实例以及其他可能写入目标数据的进程，再取得数据库与对象存储的一致恢复点。仅停止一个实例、分别在不同写入时刻复制数据库和对象目录，不能证明备份一致。
- 恢复演练从独立保存的备份副本开始，校验后恢复到新数据库与隔离对象目录；原数据不覆盖，原备份不改写。仅在明确创建成功的隔离目标上执行恢复，不通过全局所有权重分配或无条件删除现有库来处理失败。
- 演练使用空 Redis，不导入历史登录态、验证码、一次性票据或旧锁；重新登录并重建可丢弃状态。验证旧会话失效、正常认证可用、代表性主从业务与附件关联一致，并实际下载对象核对字节或哈希。只验证数据库导入成功或应用能启动不足以证明恢复成功。
- 恢复启动必须通过 Flyway 校验，不关闭校验或通过自动 repair 掩盖制品与历史不匹配。应用代码回退不等于数据库回退：未改变数据库的启动失败可回退到已验证制品；涉及迁移时按[数据库发布规则](../development/database.md#正式发布与升级规则)选择兼容版本或成套备份恢复。
- RPO / RTO 必须注明恢复点、计时起止与范围。停写快照中的数据无丢失，不代表持续写入场景的 RPO 为零；已有基础设施上的恢复计时不包括全新主机安装，也不构成整机容灾承诺。周期备份、证书续期与外部告警由部署设施安排，不能由一次演练推导其已经自动运行。
- 演练结束还原入口配置及原服务，验证各节点和原业务可用；停止隔离进程，清理临时认证材料并保留受控证据。备份内的私钥、凭据与配置按生产密钥材料保管，不进入仓库或公开日志。

## 当前实施状态

共享 Redis 状态、实例注册与定向诊断、S3/MinIO 与 FTP 实现、Quartz JDBC 集群、PostgreSQL 跨实例互斥、可信代理和优雅停机均已落到代码与配置。外部存活与就绪探针尚未提供。多实例部署不得使用 Local 文件存储；LOCAL 缓存管理当前只查询和清理接收请求的节点，尚未提供集群广播。

发布前仍必须在目标基础设施执行双实例环境验收，覆盖缓存可见性、无粘性登录、Trigger 唯一获取、资源互斥、跨节点附件读写及单实例退出恢复。环境验收是发布门禁，不能由单元测试替代。
