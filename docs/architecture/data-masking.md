# 数据脱敏架构

## 能力边界

数据脱敏用于降低已授权业务数据在接口、日志和页面中的非必要暴露，不替代接口鉴权、数据权限或存储加密。

- 业务隐私字段通过 `@Masked` 在 JSON 出站边界生成脱敏副本，不修改 Entity、Form 或原始 VO；
- 注解默认脱敏，只有显式声明的稳定权限码校验通过时才输出明文；安全上下文缺失或异常时默认脱敏；
- 当前用户个人资料使用独立 VO 返回本人信息，不复用后台管理详情的脱敏 VO；
- 密码、Token、验证码、私钥、密钥和一次性凭证不得通过普通权限放行，原则上不进入响应 VO；
- 操作日志先解析 JSON 树并递归清除凭据字段，再执行截断；无法解析且命中敏感标记时整体清除。

## 用户联系方式试点

用户管理详情中的手机号和邮箱默认脱敏，`sys:base:user:sensitive:read` 权限允许查看明文。该权限属于稳定功能 `sys/base/user`，只通过 Flyway 迁移维护。

无明文权限的编辑页面只读展示遮罩值。操作者主动选择重新填写后才提交新值；未重新填写时请求省略该字段，由后端保留原值，禁止把遮罩字符串写回数据库。

## 非目标

当前不提供数据库驱动的动态脱敏规则、MyBatis 查询结果改写、前端自主放行、通用导出脱敏或业务字段存储加密。新增身份证、银行卡等高敏字段时，应先评审明文查看审计和存储保护要求。
