# 线程诊断

## 定位

线程诊断面向超级管理员，使用 JDK `ThreadMXBean` 获取指定在线实例的平台线程、实时调用栈、CPU 热点、锁信息和死锁信息。该能力不依赖 Java Agent、外部命令或跨请求诊断会话。

## 权限和接口

- 页面访问权限：`sys:monitor:thread:access`；
- 热点、全量快照和死锁采集权限：`sys:monitor:thread:collect`；
- 所有公开 Service 入口额外复核真实 `administrator` 身份；
- 列表和详情使用查询接口，高开销采集使用命令接口并记录操作审计；
- 采样最长 5 秒、热点最多 50 个线程、堆栈最大 256 层。

## 多实例路由

实例每 10 秒向 Redis 注册一次，注册详情 TTL 为 30 秒。注册信息包含实例 ID、版本、启动时间、最后心跳和内部管理地址；前端实例列表不返回内部地址。

收到跨实例请求的节点只根据注册表解析目标地址，并携带当前 Sa-Token 调用目标节点内部接口。目标节点重新执行登录、权限和管理员身份校验。生产环境的 `SMART_MANAGE_INTERNAL_BASE_URL` 必须是其他应用实例可直接访问的 HTTPS 内部地址，不能填写公网入口或负载均衡地址；集群内部应由服务网格或反向代理提供 TLS。

## 能力边界

- 线程列表不采集堆栈；选择线程后按 ID 获取实时堆栈；
- 热点线程通过两次线程 CPU 时间采样计算增量占比；
- 全量快照包含受限深度的堆栈、Monitor 和 Synchronizer；
- 死锁检测使用 JVM 原生死锁检测；
- `ThreadMXBean` 不包含虚拟线程，项目启用虚拟线程前必须重新设计诊断实现；
- JVM 已无法响应 HTTP 时，应用内诊断同样不可用，应使用部署平台、`jcmd` 或 JFR 等外部手段。
